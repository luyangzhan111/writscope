# M3j：同事件多项状态转换离线子步

日期：2026-10-23。性质：离线机制验收；输入由测试手工构造，**不是模型提取结果**。

## 已实现

[版本化批次内核](../../../scripts/m3j_transition_batch.py)接受一个可信事件对应的一次响应，响应的 `items` 可含 1–8 项约束、授权或生命周期提案；`no_change` 必须单独出现。运行器从公开输入补齐 case、事件、序号、配置和调用 ID，拒绝响应自带这些可信身份字段。每项仍使用唯一精确引文和 M3f 的活跃约束、主体/版本引用规则。

内核按条目顺序在临时状态上验证，全部通过才提交。任一条目失败，整批约束、授权和例外均不落盘；失败事件被消费并写入批次记录，后续事件停止处理。记录包含原始提案、批次 ID、接受状态、失败条目索引、原因、前后状态哈希和已接受引文；可从批次独立重放并发现篡改。旧单转换入口和历史真实运行保持原样。

## 验证

`tests/test_m3j_transition_batch.py` 的 5 项离线测试通过：同一 e001 两项约束提交、后续 c002 局部授权、第二项无效时原子回滚和停止、工具事件伪授权拒绝、响应身份字段伪造拒绝、批次结构和回放篡改拒绝。测试中的两项约束为机制输入，**不是对 e001 语义提取正确率的证明**。

本步新增真实模型请求 0 次，未生成模型 token 或费用。批次解析器尚未接入实际 provider、请求提示词、费用闸门和终点模型复核；M3i 任务背景账本也尚未与该批次入口合并。截止点前历史回查已有独立 [M3k 离线入口](m3k-history-lookup.md)，下一步需把这些组件纳入同一轨迹。
