日期：2026-10-23。执行类型：**离线契约与请求预览**，实际模型调用 0 次。没有新增付费授权，也没有模型方法成绩。

## 请求与响应

[版本化契约](../../../scripts/m3o_interaction_contract.py)和[提示词](../../../prompts/incremental_interaction_v1.md)规定每次模型响应只能是两种严格 JSON 对象之一：

| `kind` | 模型提交 | 运行器负责 |
| --- | --- | --- |
| `lookup_request` | 当前事件需回查的原始事件 ID 列表 | 按当前可信历史前缀、每次事件数与全轨次数限额校验；读取原文并在后续请求中附回查结果。模型不能自报身份、未来事件或工具返回内容 |
| `extract` | 当前事件的任务背景精确引文和最多八项状态变更；无变更时单独提交 `no_change` | 从可信事件补全 case、事件、序号、调用 ID；分别生成 M3i 任务背景批次与 M3j 原子状态批次，后续由状态引擎决定是否接受 |

逐事件请求含截止到当前事件的公开历史、同一公开工件与注册表、**前一事件**的状态和任务背景，以及当前事件已发生且可重放的回查结果。基础公开证据哈希与完整上下文清单基线相同。模型不能提交角色、时点、字符跨度、状态哈希或费用；任务背景与状态变更引用必须是当前事件的唯一精确引文，工具消息不得产生任务背景或授权变更。回查意图和提取结果互斥；一次回查的模型续答会消耗 M3n 的额外 provider 尝试额度。

新增通用终点请求构造函数：从完整的运行器状态、任务背景和每次原始时点均可回放的回查记录构造 `incremental_review` 请求，并由调用方显式提供模型配置。它复用 `source_quote_v1` 三轴输出契约；M3m 保存的人工计划请求不被改写。当前 DeepSeek 适配器仍无原生工具调用，M3o 的回查是应用层 JSON 协议，真实调用与续答流程留给 M3p。

## 验证与限制

- `tests/test_m3o_interaction_contract.py` 的 6 项测试通过：三历史共 15 个事件前缀均可离线生成请求并提交无语义的 `no_change` 脚本转换；与基线公开证据哈希一致；回查续答按原时点重放；未来事件、伪造身份、工具授权、错误引文、错误先前状态和超额回查被拒绝；终点请求可绑定显式模型配置；篡改请求即使重写工件哈希仍被回放发现。
- [三历史初始请求预览](../../../reports/local/m3o-interaction-preview-20261023-final/run.json)已保存并验证，状态 `prepared`、实际模型调用 0 次。较早的预览目录 `m3o-interaction-preview-20261023` 保留为修订前历史草稿，其运行器哈希与当前源码不同。
- 这些 `no_change` 脚本转换只检查交互接口与事件推进，不代表任务背景或授权语义提取正确。M3o 不调用 provider、不提交真实模型状态、不生成终点模型结果，也不把 M2b 与 M3l/M3m 的不同执行类型比较。

下一步 M3p 将用脚本 provider 把请求、可选回查续答、任务背景、原子状态批次、终点模型响应与 M3n 账本接入一条可回放轨迹。M3o 只定义和校验交互；跨组件原子提交与完整故障停机在 M3p/M3q 验收。
