# S3.4：隔离状态诊断与累计成本核查设计

日期：2026-10-24；更新：2026-10-25。状态：**设计已完成；随后完成 c003 单人规格审核、离线诊断与成本对账，见 [单例记录](../../experiments/s3-4-c003-isolated-review.md)；另完成 c002/c001 有限历史审核、两条固定历史全部前缀的[v2 人工状态编译](../../experiments/s3-4-c001-c002-state-compilation.md)，以及本批六分支的语义判读与 [v3 跨事件生命周期图](../../experiments/s3-4-lifecycle-alignment-review.md)**。更多组合未穷举，独立审核和模型条件消融未运行。新增模型请求 0 次，不产生新付费授权或方法成绩。

## 目标与边界

本诊断回答两个有限的问题：逐事件保存的模型提取与经审核的人工状态在哪里分叉；现有运行的全部前序成本能否从原账本核对到终点或停机点。它不估计“换成正确状态后模型会怎样回答”，也不把人工状态当成第四个公平参评方法。观察轨迹、人工轨迹及新版策略反事实必须分开保存；旧失败、原评分和原请求/响应字节不得改写。

按 [协作规则](../../../AGENTS.md)与[数据契约](../../../specs/data-contracts.md)，参考状态、标签、隐藏测试及设计答案不得进入任何被测模型请求或工具沙箱。现阶段 `oracle_diagnostic` **只允许评测器侧的确定性结构回放和成本审计**。评测协议中曾写的“人工正确状态 + 同一最终复核流程”在此限定为离线结构/范围核验；若将来要让模型读取人工状态，必须先由用户明确修改隔离要求、版本化协议并另行授权费用。单独付费授权本身不能解除参考材料隔离。

### 私有审核包 v1（原设计；c003 已实现子集）

每个案例一份 manifest 和五个按 `seq` 排序的事件条目：

```text
manifest: schema_version, case_id, decision_point, public_bundle_hash,
          source_revision, policy_id, annotation_status,
          reviewer_ids, review_notes, annotation_hash
event:    event_id, seq, visible_prefix_hash, context_batch,
          transition_batch, expected_poststate_facts,
          rationale, uncertainty, item_review_status
```

`context_batch` 使用现有 M3i 原文/引用结构，`transition_batch` 使用现有 M3j 一事件原子批次结构；空批次也须显式保存。`expected_poststate_facts` 由审核者另按原文确认每个前缀应保留的活跃约束、局部例外、撤销/替代关系和任务背景；以语义字段而非运行器生成 ID 表达，不能直接抄引擎输出充当独立预期。可信 `event_id/seq/role` 由运行器从公开事件补齐，不信任私有条目自报的来源。审核说明解释应抽取或不抽取什么、授权的对象/版本/操作/条件/撤销关系；人工判断允许 `disputed`，此时不产出“正确状态”结论。为首例重点核对：e001 的客户端本地映射是任务背景；e004 的最小改动/不增接口是任务背景；c002 e005 许可仅覆盖本次 v1 字段替换；c003 e005 仅涉未来 v2，不产生 v1 例外。引用必须是当前可见可信用户事件中唯一精确原文；程序通过结构和范围校验不等于人工语义审核。

编译器从空状态按时点逐条调用现有版本化的任务背景账本与原子状态引擎，保存每个前缀的转换/拒绝记录、状态哈希与任务背景哈希，并将生成状态与独立审核的 `expected_poststate_facts` 比较。来源/引用/批次结构或审核状态无效输出 `annotation_invalid`；审核过的合法语义被策略拒绝，或生成状态与独立预期不符，输出 `oracle_compile_mismatch` 与首个分叉点，作为更新/策略待查证据，不能把该生成状态称正确状态。任何失败均停止，不跳过问题条目凑终点状态。每次重新编译须得到相同哈希。私有审核包只在评测器进程内可读；方法运行器的文件白名单、provider 请求构造器和工具沙箱均不得接收其路径、内容或派生答案。

### v2 已实现范围

c001/c002 的 [v2 契约](../../../specs/s3-4-annotation-v2.md)在独立 catalog 中保存任务背景、约束、授权及例外引用，从空状态核对全部五前缀。不同运行 ID 通过类型、来源事件、精确引文及完整对象范围解析；重复依据或错误类型/悬空引用即拒绝。原 predicate 字典布局不自动归一化，表示差异留待语义判读；旧单提案契约不支持任务背景的事实与模型错误分开。非空 supersedes/updated_by 或非 active 状态明确不支持，尚不覆盖通用撤销、替代和重授权。

后续[单人语义判读与六类边界](../../experiments/s3-4-semantic-lifecycle-review.md)把两份确切 predicate 在本批声明上判为等价，保留原 v2 差异记录。生命周期合成扩展已有独立预期、失败停止和回放；v2 对这类完整生命周期状态仍明确拒绝，没有推断其跨轨迹等价。

之后的[独立 v3](../../experiments/s3-4-lifecycle-alignment-review.md)保留本批跨事件撤销/替代/歧义和历史例外，结合原批次回放与 ID 改名控制核对六分支 37 组前缀。它不改变 v2，也不将改名控制当作独立模型或金标准；更多组合及同事件内部替代链未穷举。完整字段与拒绝条件见 [v3 契约](../../../specs/s3-4-lifecycle-graph-v3.md)。

## 三条隔离轨迹与归因

1. **观察轨迹 O**：先用原运行验证器无网络重建，记录每事件的模型原始响应、解析结果、候选任务背景/状态批次、接受/拒绝、状态前后哈希及终点。缺响应或停机后续事件标 `not_attempted`，不能补造状态。
2. **人工轨迹 R**：只在 `reviewed` 审核包上，从空状态确定性编译并逐前缀核对独立预期；使用与观察轨迹相同的公开前缀和候选影响，但不读取模型、凭据或网络。仅预期一致的前缀可称 R 的正确状态；分叉处保留审核预期和生成状态，停止向后归因。R 的身份为 `oracle_diagnostic`，绝不覆写 O。
3. **逐前缀对照 D**：先比较任务背景及候选语义，再比较接受状态。跨轨迹匹配按来源事件/唯一引文、对象、版本、字段、操作、适用条件、撤销/替代关系；状态 ID 只作轨迹内引用，不能单凭 ID 相同/不同判语义。无法唯一对齐时记 `alignment_ambiguous`，保留两边原文及理由，不强行裁定。

| 观察条件 | 可记录的诊断 | 不能据此声称 |
| --- | --- | --- |
| 模型候选与审核项在语义/来源/范围上不符 | `extraction_semantic_error`，按影响/授权/任务背景及对象/版本/操作细分 | 结构接受说明语义正确 |
| 首个分叉点处，观察前状态与独立预期一致、提案与审核项语义一致，但引擎生成状态与独立审核的后状态不符 | `state_update_or_policy_error_candidate`，附原始前缀、规则和差异；再查内核或审核预期 | 在上游已分叉时把下游差异强归于更新层 |
| 提案本身有错且旧策略仍接受 | 可同时标提取错误与策略放行；例如 M3e 的跨版本引用 | 只选择一个责任层，或按新规则追改旧运行 |
| 解析、provider、超时、预算或批次拒绝导致停机 | `run_or_format_failure`，终点 `not_attempted` | 把未生成的终点判为错误决策 |
| 状态与人工状态不等、终点三轴却命中参考 | `masked_state_error`，终点正确与状态质量分开 | 状态没有问题或方法更优 |
| 终点三轴与参考不符 | `terminal_mismatch_observed`，连同终点输入和状态差异 | 在状态不同的情况下唯一归因于终点复核模型 |

影响、授权、最终决策各成一列；一事件可有多个错误标签。只有同一输入、同一有效状态且前序状态无歧义时，才能把终点不符暂记为 `review_error_candidate`；否则记 `mixed_or_undetermined`。原模型输出是事实记录，不用人工轨迹的结果给它改分。已保存的 M3s 终点响应引用当时生成的状态 ID，不能套用到 R 的状态；它既不是“正确状态下的模型回答”，也不能用于计算状态消融带来的准确率变化。可以离线计算 R 的结构性范围覆盖与参考三轴关系，明确标为 `deterministic_scope_check`，不称模型复核。

先对 M3s c003 做上述语义审核与对照；M3c 停于 c002 e005、M3e 的旧策略接受均保留独立版本和失败边界。单例开发诊断不能推断错误率、状态维护收益或三方法优劣。

## 成本对账与输出

`observed_cost` 必须从 O 的所有实际尝试汇总到终点或停机点：提取、状态/任务背景更新、回查请求及读取、终点复核、验证与失败尝试；重试如有也计入。对每阶段分别列 provider 输入/输出/缓存/推理 token（注明字段是否缺失）、本地耗时、预留、估算费用、账单费用与来源。缓存字段依提供商定义，不能把子集重复相加；`unknown` 不换算成 0。M3s c003 当前应对上 **5 次提取 + 0 次真实回查 + 1 次终点 = 6 次真实请求**；未使用的两次上限不是实际成本，提供商实付账单仍为 `unknown`。人工标注时间及 R 的离线 CPU/墙钟单列为 `diagnostic_cost`，不充作原方法或提供商费用；未执行的 oracle 条件模型请求无成本数字。

拟生成独立、不可覆盖的 `reports/local/s3-4-*/`：`diagnostic.json`（每前缀双轨摘要与多标签归因）、`cost_reconciliation.json`（原账本逐次和分阶段核对）、`provenance.json`（O 工件集、公开包、审核包、源码/策略哈希及验证结果）、人可读 `review.md`。私有审核包和参考原文不复制进公开报告；需展示的错误片段只用已公开原文和必要的审查说明。结果只可标为 `oracle_diagnostic`，正式三方法报告不得合并其质量或成本。历史不同模型配置/提示词/策略的运行分别核账，不拼接为同轮成绩。

## 实现与验收顺序

1. 建私有审核包格式与校验器；独立审核 c003 每一事件的任务背景、状态批次、预期后状态和歧义，记录审核者/分歧。未达 `reviewed` 不进行正确状态归因。
2. 建只读隔离入口：验证 O，编译 R，阻断私有材料进入请求构造器/工具沙箱；注入非法引文、未来事件、篡改哈希、争议条目时应停机，无 provider 调用。
3. 生成逐前缀对照与多标签归因；验证 ID 不同但语义相同、歧义匹配、旧策略接受错误提案、失败后 `not_attempted`、不能复用旧终点响应等情形。
4. 从原账本重算总成本，逐次和总计相符；缺失账单仍 unknown，失败尝试仍计入，人工诊断成本独立。对 M3s 的 6 次请求和零回查作实物核账，不修改原报告。
5. 保存来源哈希和只读回放命令；复验结果一致后再写实际发现。届时仍单列诊断证据，S3 退出及 S4 正式比较按各自剩余门槛判断。

前四项的 **c003 单例子集** 已无网络运行并通过回放，见[验收记录](../../experiments/s3-4-c003-isolated-review.md)；c001/c002 在有限历史审核之后完成全部五前缀的[v2 编译和局部例外对齐](../../experiments/s3-4-c001-c002-state-compilation.md)，两处表示差异及六类边界另经[补充审核](../../experiments/s3-4-semantic-lifecycle-review.md)，本批跨事件生命周期图由 [v3](../../experiments/s3-4-lifecycle-alignment-review.md)对齐。独立金标准和模型条件消融未形成，更多组合不能由本批推断；S3 退出仍未验收通过。下一步先汇总离线证据矩阵。
