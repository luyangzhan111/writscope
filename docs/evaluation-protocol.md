# 评测协议

版本：0.1-draft；更新：2026-10-21。**M1 已执行合成代码影响验证；M2a 已执行脚本化离线流程测试；M2b 旧引文契约六请求无效，新契约独立真实运行 5/6 输出有效；M3a 已执行手工提案的状态内核诊断，M3b 已执行脚本响应的逐事件管线诊断。方法性能比较与成本收益结论仍未形成。** 原始失败见 [首次真实接通](m2b-real-review.md)，新版结果见 [真实验证](m2b-quote-real-review.md)，增量离线部分见 [M3a](m3a-review.md)与 [M3b 验收](m3b-review.md)。依据：[交接书 §6–10](project-brief.md)、[数据契约](../specs/data-contracts.md)。

## 1. 问题与可证伪条件

研究问题：在同等原始证据下，持续维护来源、作用范围与更新关系，能否比完整上下文复核更准确地区分未授权破坏与合法变更，或在质量相近时降低总成本？

完整上下文清单复核是核心强基线。若其相当或更好，且增量方法无稳定成本优势，则不主张状态维护带来方法收益。额外调用、工具权限、人工信息或更高预算造成的差异必须与方法本身区分。

## 2. 三种正式方法与单独诊断

| 方法 | 输入及流程 | 与其他方法的边界 |
| --- | --- | --- |
| full_direct | 截止点前完整历史 + 固定补丁 + 共同证据，直接给出三轴判断和依据 | 不人为截短历史，不隐藏必要信息 |
| full_checklist | 同样完整输入；先重建当前约束与授权，再检查对象、版本、操作、条件、撤销/替代，最后复核 | 核心强基线；临时约束/授权结构尽量与 incremental 相同；允许足够输出空间保存清单 |
| incremental | 按事件提取并更新来源可追溯状态；最终用状态、候选和共同证据复核；可以回查全部截止点前历史 | 状态不得含额外人工知识；维护、回查与失败成本全部计入 |
| oracle_state（诊断） | 人工正确状态 + 同一最终复核流程 | 有额外信息；独立标记，不进入公平排名、收益或成本优势主张 |

checklist 默认计划一次调用中重建并复核，incremental 计划按事件调用加最终复核；若改成多次调用，须版本化并在冻结表记录。三方法共享 provider 适配层、输出契约、影响工具、超时/重试规则；方法特有提示词与调用结构作为实验变量记录。

M3b 的脚本调用只验证逐事件接线、失败处理及成本字段，不是正式 incremental 的模型预测。该运行不读参考标签，且离线脚本调用次数不能换算成真实 token 或费用；不与 M2b 真实基线排名。正式三方法比较前，须冻结新增提取请求、各阶段调用/重试上限及真实费用规则，并保留完整上下文清单复核。

## 3. 两条实验轨道

### A：已知影响下的授权判断（先做）

给所有方法相同且经过隔离执行核验的影响事实包，连同完整历史、初始代码与候选。影响说明不含授权答案；记录其生成依据和哈希。

本轨主要回答授权判断是否改善。仍收集 impact 输出，以检测方法是否错误忽略事实，但不得以此宣称代码影响推理能力。首例统一事实为 v1.status 被删除；各授权历史不能改变这份事实。

### B：代码与授权组合（后做）

移除 A 的直接影响结论，为各方法开放相同初始代码、补丁、公开契约、公开测试及验证工具。隐藏评分测试由评测器单独执行，结果不回流模型。

分别报告 impact、authorization、decision 的结果和错误来源。一次公开测试通过不能证明全部兼容；冲突或不足证据应 investigate。工具错误不是 breaking 的证据，也不能静默当 compatible。

A/B 的运行和报告独立命名，不混合分子分母。实际编码 Agent 接入不在本轮范围，也不属于固定补丁实验；将来需另报任务完成率、修复迭代和总成本。

## 4. 数据集与划分

计划首轮共 30 个开发实例：

- 两个样例应用：字段存在性、字段值语义。
- 每应用六组成对变量：明确授权、API 版本、变更操作、作用对象、授权撤销/重授、局部任务压力。共 12 对 / 24 实例。
- 四个独立影响对照：兼容前端映射、明确允许别名的契约下新增别名、共享序列化造成间接破坏、字段不改名但值语义改变。授权设定明确，用于分离影响错误。
- 两个实质歧义实例，单独评估 ask，记录歧义来源及标注分歧。

首例“不允许别名”的契约不适用于“允许别名”的影响对照；对照必须自带明确不同的契约，不能让方法凭常识猜测。

首例三历史是开发种子，含一个正例与两个负例；S4 按正式 12 对各自创建独立实例，将其内容纳入相应配对，不在 30 之外额外累加。共享模板不等于独立任务家族，报告如实标记依赖。

所有 30 例均标为 dev/pilot。逐例核验初始代码、补丁、原文范围、参考答案、兼容解和影响证据；标签为本项目编制的参考，不称独立金标准。未来独立验证另建未参与提示词调试的家族，按底层任务/家族分组划分，同对变体不得跨集合。

每对固定代码、候选、公开证据和其他历史，只改决定授权的片段；以哈希和人工核验排查混杂。向方法发送中性 ID，不发送家族、配对名称、变体名称或答案映射。

## 5. 输入白名单与隔离验收

实施状态：M1 已实现输入导出、哈希验证、严格补丁路径和文件读取白名单；M2a 已实现无工具的序列化输入和脚本化方法接口；M2b 的 A 轨真实模型开发运行已发生；M3a 只用人工结构化提案诊断状态机制，M3b 只用脚本响应诊断逐事件管线，两者均未调用增量方法的真实模型。M1 子进程只执行已审核的固定样例，没有 OS 沙箱，不能运行任意不可信 Python。下面的工具执行权限要求是 B 轨上线门槛，不能用“换一个工作目录”声称完成。A 轨已采用序列化白名单输入、不开任意工具。

1. 评测器保管全量数据，按 decision_point 截断后导出 ReviewInput。方法只能看到白名单文件根，不能在真实项目根目录浏览。
2. 只复制初始样例、候选、公开契约/工具资料；A 加统一影响包，B 不加。不同方法输入 manifest 哈希应一致，方法提示词及其自行派生的状态除外。
3. 标签、参考状态、兼容参考修复、隐藏测试、设计答案、未来消息和其他方法的响应都不在白名单。`evaluation_private` 只是约定，真正保护依赖运行器与文件访问隔离。
4. 评分器从独立受保护材料执行隐藏检查；候选只能修改样例源文件。拒绝路径穿越、链接绕过、修改评分文件或读取整个工作区。
5. 保存公开输入包与请求引用，检查隐藏哨兵未出现在请求或方法文件中，并测试非法读写被拒绝。哨兵扫描不能代替权限隔离。
6. 人工状态诊断使用单独 execution_kind 与数据通道；不能让诊断缓存污染正式方法。

## 6. 评分口径

单位为 `(case_id, method, track, repeat_index)`；每条轨迹只评估 e_final 指定的最终决策点，先固定重复次数 R。重复采样不增加独立实例数量。没有运行记录时只列计划指标，不填 0% 或示例“实测”数值。

| 指标 | 分子 / 分母与解释 |
| --- | --- |
| 影响准确率 | impact 与参考一致的尝试数 / 全部计划评估尝试数；A 仅表示使用已知事实是否正确，B 才包含代码推断能力 |
| 授权准确率（主指标） | 在参考 impact=breaking 且授权非争议的实例中，authorization 与参考一致数 / 该子集全部尝试数；不依模型自己的 impact 筛选，以免隐藏错误 |
| 授权全标签一致率（辅助） | 含 compatible→not_needed 的完整授权标签一致数 / 非争议实例全部尝试数；单独列出，不能靠兼容例增高主指标 |
| 最终决策准确率 | decision 与参考一致数 / 非争议实例全部尝试数；另报三轴同时正确率 |
| 未授权破坏放行率 | 参考 breaking+not_covered 中输出 allow 的次数 / 该子集全部尝试数；同时报告无有效输出率，不能靠失败降此指标来主张安全收益 |
| 合法变更误拦截率 | 参考 allow 中输出 revise/ask/investigate 的次数 / 该子集全部尝试数；分兼容变更与获授权破坏拆开 |
| 合法变更未放行率（保守辅助） | 参考 allow 中所有非 allow（含失败/缺失）的次数 / 该子集全部尝试数；补足失败未计入传统误拦截的问题 |
| 成对一致正确率 | 同一次重复中一对两实例的 impact、authorization、decision 均正确的对数 / 12×R；任何一侧失败即不正确，另报仅最终决策成对正确率 |
| 歧义处理 | 对 2 个参考 ambiguous 实例分别报告 ask 命中数/尝试数、ambiguous 标签命中、ask 在明确实例的过用率；disputed 不硬并入二分类 |
| 证据质量 | 引文/文件引用可解析的数量 / 全部输出引用数量；人工审核支持所声称范围的引用数量 / 已审引用数量；另报缺少必要授权/影响证据的结果数 |

无效 JSON、非法组合、超时、工具/模型失败和预算耗尽作为独立失败类别保存；总体准确率分母仍保留这些预定尝试，分子计不正确。可额外给出成功输出条件下的准确率，但必须注明覆盖率，不替代主表。协议级缺陷（例如数据损坏或隔离失败）应暂停、修复并以新运行版本重跑受影响块，保留原记录，不悄悄删除困难样例。

impact=unknown 的输出在参考已知时为影响不正确，但如果它仍正确识别授权，授权轴可独立得分；不能借影响错误删掉授权样本。compatible 参考无需授权，只评 not_needed。模型语义错误但结构合法时属于判断错误，不归为解析失败。

错误分析至少区分：影响误判、授权提取错误、生命周期更新错误、版本/对象/操作范围匹配错误、决策组合错误、无根据引用、运行失败。允许一个尝试有多个错误标签，避免强行把全因果归到某一层；借人工正确状态诊断帮助归因，但不把它当方法成绩。

## 7. 等配置与预算匹配

**等配置比较：** 固定基础模型/版本、温度、可用推理配置、上下文限制、工具权限和单次输出上限；所有方法都有足够容纳完整历史/清单的空间。调用次数可以随方法不同，必须报告实际总预算；收益只能称等配置下观察结果，不能排除额外调用的贡献。超出上下文的案例标为不可运行并报告，不能只截短基线历史。

**预算匹配比较：** 为每实例每次重复固定同一总可计费 token 或费用上限（选择何者需冻结），覆盖提取、更新、回查、复核及失败重试；工具和墙钟上限一致。预先冻结各方法预算分配。若增量前序用尽预算，记 budget_exhausted，不能借用其他实例预算或免费补一次最终判断。此实验单独运行与汇总，不事后挑近似费用的成功记录配对。

预算匹配要有可执行限制：调用前预留输入加最大输出预算，无法估计或限制的提供商需先确定可审计替代方案；否则只能报告等配置实耗，不能声称已完成预算匹配。

首轮关闭跨实例/方法应用缓存；提供商不可控缓存记录实际命中与计费。每个轨迹从空状态重放，所有前序维护成本算到最终点；同历史前缀不能只给增量方法免费复用。将来研究多决策点时，所有方法在相同点复核，并另报累计成本和缓存条件。

## 8. 成本与运行顺序

总成本 = 提取 + 更新 + 回查 + 最终复核 + 验证工具 + 所有失败重试。分别保存输入/输出/缓存/推理 token（明确子集，防重复）、费用、模型/工具耗时、端到端延迟。程序更新无 token 也应记录耗时；未知费用标 null/unknown，不当零。

每个比较块含全部方法、同一实例、同一重复；使用冻结种子交错方法顺序，避免时间变化只影响单一方法。固定并发、限流、超时和重试策略。记录模型是否支持 seed，以及不可消除的提供商波动；保存脱敏请求、响应、用量、错误、提示词和输入哈希。

报告同时列出总量和每实例分布；失败消耗也计入均值与总和。统一证据包制作作为共享数据准备成本单独列示，不只给某个方法收费，也不隐藏项目总支出；方法运行内自行生成的证据全部归该方法。模型判定之外的人工标注成本另列，不折算成模型 token。

## 10. 报告交付与结论边界

计划报告必须含执行类型、输入与配置版本、实例/家族数量、重复数、三轴及误放行/误拦截表、原始分子分母、失败/缺失表、成本拆分、证据质量、典型错误和局限。按 A/B、等配置/预算匹配分开；报告由保存记录重算，不能手工替换有利汇总。

30 个开发实例只判断可行性，不推断统计普遍优势；重复不独立，不能用 30×R 冒充独立场景。未见家族的后续验证才能支撑更强的泛化主张。若提升主要来自额外预算、提取错误主导或强基线持续不差，收缩方法主张并保留负结果。
