# c004 真实回查续答拒绝：条件与证据引用离线诊断

日期：2026-10-26。承接已用完的 v5 单轨授权，本步只读回放并离线设计下一版；新增真实请求0次，不改写原调用或状态规则。

## 保存响应揭示的问题

模型自主请求e002，运行器成功返回工具原文。续答正确从报告提取了候选摘要并将其判为与当前patch不符，但输出了 `kind=candidate_patch_sha256` 与 `evidence_refs=["e002"]`。在此实现中，内核支持的特殊候选摘要条件名为 `candidate_sha256`；`evidence_refs` 必须是公开artifact注册表ID（如 `patch`），历史事件ID只用于回查，不能用作artifact证据引用。由于现交互schema把条件类型和引用项都声明为普通字符串，格式验证没有提前显示这些合法值。

原v5运行器将同一原始续答交给范围内核；内核以 `unknown public condition evidence reference` 拒绝，并原子停止。拒绝是安全的。由于调用停止，模型没有被允许再作修正，也没有终点；本记录不推演后续模型答案。

## 离线修订候选

- 新增 [interaction v7提示](../../prompts/incremental_interaction_v7.md)，明确区分历史事件ID与artifact ID，固定支持的 `candidate_sha256` 拼写，并要求把报告摘要标为不满足时保留原值，不把工具事实当授权。
- 新增 [interaction quote v4适配](../../scripts/s3_interaction_v4.py)：请求schema按公开bundle动态把条件类型限制到当前支持值、摘要格式限制为小写64位SHA-256、证据引用限制到注册表中的artifact IDs；本地解析也拒绝schema之外的值。它不映射事件ID、不补字段、不修复响应。
- 四项新离线测试验证原真实响应在新契约下仍拒绝、动态schema排除 `e002`、人工构造的规范表示可通过状态提交，并由确定性评估保持 `not_covered/revise`。加上局部映射三个回归，7项测试通过。

人工控制只证明合法表示及保守评估路径存在，不是模型输出或正确率样本。新prompt/adapter尚未接入新的完整运行器或付费计划；v5冻结入口、六份真实调用、失败报告和费用不变。后续如验证v7，需建新版本运行器/预检、重核官方价格，并重新取得确切scope的预算及数据外发授权；v5的3元授权已用，不能续用。
