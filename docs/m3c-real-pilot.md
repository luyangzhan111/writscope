## 运行与核验

独立入口为 `src/writscope/m3c.py`。`preflight` 不读取凭据或联网；检查公开包、证据一致性、请求白名单、模型/提示词/代码/依赖哈希及预算。`run` 对照预检后才读取 `DEEPSEEK_API_KEY`，每步请求动态构建并在发出前预留。原始响应和提供商 token 用量与状态转换分别保存；`verify` 无网络逐步重建请求与状态；`score` 在运行保存后才读取评测器侧草稿标签，输出到独立目录。任何后续提示词、契约或代码调整都需要新预检和新运行，不追改这次记录。

本步仍缺少任务背景、一事件多转换、跨事件回查、真实最终复核，以及 30 实例和独立未见家族。终点判断由 M3a 确定性逐影响匹配生成；有效结构不保证模型正确理解用户语义。

- 实际发起 **10 次**请求，均返回 token 用量；c001 的 5 次转换被接受，终点评估 `breaking / not_covered / revise` 与项目草稿参考一致。c002 前 4 次转换被接受；e005 模型提交带有 `AuthorizationDraft` 的 `supersede`，目标为 `c_v1_profile_status_contract`。**该 ID 确实是 c002 当前状态中的有效约束 ID，但不是授权 ID；当前状态没有授权。** 内核按 `supersede` 授权替代的目标类型规则，以 `authorization supersede target is missing or inactive` 拒绝转换，不生成 c002 终点判断。c003 因首次失败全局停止而**未发起请求**。
- 因而三个计划实例中，仅 **1/3 有有效终点输出且三轴与草稿参考一致**；c002 为真实提取/状态转换失败，c003 为按规则未尝试，不可把二者算作模型错误判断，也不可从 c001 推断方法准确率。c001 的 e001 提案引文和角色来源合法；e002/e003 工具内容及 e004/e005 被提取为 `no_change`。c002 e005 错在把新授权选择为替代已有授权的操作，并将约束 ID 放进该操作的目标；其 `conditions=[]` 还没有表达“本次”候选哈希绑定。不能在事后替它改成 `grant` 或重算有效输出。
