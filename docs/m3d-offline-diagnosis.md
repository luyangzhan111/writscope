# M3d：M3c 失败归因与离线提取修订

日期：2026-10-21。状态：**只完成历史记录复核、版本化提示词和无网络回归；没有新的真实模型请求。** 这是 M3c 失败后的开发诊断，不追改 [M3c 运行与评分](m3c-real-pilot.md)。

## 复核结论

保存的 c002 `step_005/request.json` 在 `prior_state.constraints` 中明确列有 `c_v1_profile_status_contract`，`prior_state.authorizations` 为空。模型输出的 `AuthorizationDraft` 以 `operation=supersede` 和该约束 ID 作为 `target_ids`；状态内核要求授权 `supersede` 的目标是**活跃授权 ID**，因此拒绝。这是**操作及 ID 类型混淆**，不是 ID 不存在。旧 M3c 报告曾把 c001 的约束 ID `c_v1_profile_status_exact` 误当成 c002 的先前状态；现已根据 c002 原始请求和转换日志更正。

模型 e005 原文确实是用户对**本次候选** v1 字段替换的许可。首例规格要求把它建成局部授权例外、保留宽约束，并绑定候选哈希。保存的响应同时含 `conditions=[]`，因此即使仅把操作改成 `grant`，仍没有表达“本次”范围。结构验证可拒绝错误目标类型，但不能证明自然语言条件提取得完整。不能对旧响应做事后修补并算为有效模型结果。
