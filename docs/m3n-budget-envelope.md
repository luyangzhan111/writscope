# M3n：完整增量运行的离线调用与费用边界

日期：2026-10-23。性质：**可回放的规则草案**；没有获取新付费授权、核定当日价格或调用模型。

## 调用与停止规则

[离线预算账本](../scripts/m3n_budget_envelope.py)以 c002 五事件的 M3l 完整轨迹及 M3m `prepared` 终点请求为来源。草案为同一条完整增量运行预留最多 **8 次 provider 尝试**：每事件一次提取（5 次）、最多两次因历史回查而发生的模型续答（2 次）、终点模型复核一次（1 次）。本地历史回查本身最多两次，另记录耗时；是否需要续答由未来模型工具流程决定，未发生的调用不计为实际调用。单并发、每事件一次初始提取、每次回查最多一次续答、终点一次、无重试；每次 90 秒、请求最多 100,000 字节、输出最多 4096 token。任一 provider、用量、输出、回查、状态或预算失败立即停止；只有五事件都接受才可尝试终点复核。

费用规则在每次 provider 请求**发送前**，用实际序列化请求的 UTF-8 字节数加价格文件的 framing allowance 作输入 token 保守代理，加最大输出 token，按显式价格计算本地预留。账本先要求本地上限至少覆盖 8 次按最大请求字节数计算的最坏预留；超预算不发送。超时或用量缺失不会释放已预留额度。实际 token 和账单分别记录，缺失账单保持 unknown；已知账单小计不能当总账单。这个本地预留不是提供商侧硬封顶。

原始草案的运行器哈希对应修订前源码；当前验证器只确认修订版，原件仅供历史审查。
