## 接线与停止规则

运行器沿用未修改的 M3p 状态、任务背景、回查、终点契约：每次从先前保存的响应重建可信状态，再构造下一条请求。真实 provider 仅收到请求白名单中的公开事件前缀、工件、状态和已发生回查；`deepseek-flash` 的 Chat Completions 适配器禁用 provider 原生工具调用。每次调用前沿用 M3n 账本预留，最多五次初始提取、两次回查续答和一次终点复核；单并发、无重试、90 秒超时、首次故障停整例。回查和状态更新的本地耗时、provider 耗时及端到端墙钟分列保存。

逐次记录请求、原始文本、阶段、预留、响应元数据、输入/输出/缓存/推理 token、估算费用与失败；未知 token 或账单完整总额保持 `null`。运行 ID、提示词和公开输入由 M3r 计划绑定。已发请求若超时、缺失用量或响应无效，预留不释放；五事件未全接受时没有有效终点结果。保存后 `verify` 不读取密钥或调用网络，而是从响应逐次重建请求、状态、任务背景、回查和终点；重写工件哈希后的请求篡改仍会拒绝。

真实启动只允许 `real_model` 模式与固定 DeepSeek provider。调用方先验证 M3r 计划和新授权范围，再验证授权绑定的 M3s 运行器哈希与 24 小时内的官方价格复核时间，**之后**才读取 `DEEPSEEK_API_KEY`。M3r 的 3.00 元是本地拟议预留上限，不是提供商侧硬账单上限；本步没有创建授权回执或调用真实 provider。
