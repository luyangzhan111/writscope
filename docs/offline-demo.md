# 三案例离线演示

这个演示帮助学习者理解 WritScope 的一个核心问题：同一补丁造成同样的兼容性破坏，不同用户授权为什么会改变最终决定。它也可作为介绍项目时的本地展示页。

演示始终生成 c001、c002、c003 三个预置案例，使用打包的公开 fixture 副本、现有 `StateEngine` 和人工编写的提案计算状态及结构覆盖。补丁影响来自已经保存的 M1 公开证据。本次不执行候选代码，不调用实时模型，不读取参考答案或仓库私有目录。

## 安装与运行

在源码目录安装锁定依赖：

```powershell
uv sync --locked --python 3.12.4
uv run --offline --locked writscope demo
```

安装依赖可能访问软件包源。依赖就绪后，演示生成和查看均可离线进行，不需要 API 密钥、HTTP 服务或额外前端构建。

两个入口执行相同功能：

```powershell
uv run --offline --locked writscope demo
uv run --offline --locked python -m writscope demo
```

默认在当前目录的 `.work/writscope-demo-<唯一标识>/` 中创建一次新运行并打印输出路径，不自动打开浏览器。点击或直接打开其中的 `index.html` 即可查看。

可选参数：

| 参数 | 作用 |
| --- | --- |
| `--output <目录>` | 将本次结果保存到指定的新目录；目录已存在时拒绝覆盖 |
| `--open` | 生成后尝试用默认浏览器打开本地 `index.html`，不启动服务 |

例如：

```powershell
uv run --offline --locked writscope demo --output .work/my-writscope-demo --open
```

再次使用显式路径时请换一个新目录。默认每次创建新目录，旧运行记录继续保留。已安装 WritScope 包及其依赖的环境，也可直接使用 `writscope demo` 或 `python -m writscope demo`；演示资源随包提供，不要求当前目录是源码仓库。

## 页面中看什么

三个案例共享旧 v1 API 契约和候选补丁：页面需要 `state`，候选在服务端把 `status` 替换为 `state`。保存的公开证据表明旧契约被破坏，因此三个案例的 `impact` 都是 `breaking`。

| 案例 | 最后一条用户消息的范围 | 结构覆盖结果 |
| --- | --- | --- |
| c001 | 保留 v1 契约，只做客户端本地映射 | v1 服务端替换未被授权：`not_covered / revise` |
| c002 | 明确允许本次 v1 字段替换 | 当前候选得到局部许可：`covered / allow` |
| c003 | 只允许未来 v2 字段替换 | v2 许可不覆盖当前 v1：`not_covered / revise` |

建议介绍时按这个顺序浏览：先比较补丁与旧契约，再查看历史消息和状态，最后展开影响对应的授权与原文来源。切换案例时关注最后一条消息如何改变授权，而补丁和破坏事实如何保持相同。

这体现三个设计点：客户端实现许可不自动扩展到服务端；新版本许可不自动覆盖旧版本；明确授权的破坏可以 `allow`，破坏事实仍记 `breaking`。这里的 `allow` 只表示通过本演示评估的兼容性与授权检查，不代表其他质量检查已通过。

## 输出与可重复查看

每次运行创建三个文件：

| 文件 | 用途 |
| --- | --- |
| `index.html` | 自包含展示页，可直接以本地文件方式打开 |
| `demo.json` | 本次演示的案例、来源和计算结果，便于检查及后续展示 |
| `manifest.json` | 本次生成工件的清单与完整性信息 |

HTML 包含展示所需的数据和资源，不需要从 CDN 加载脚本、字体或样式。保留整个输出目录便于检查记录；分享时应同时说明这是人工预置提案的离线结构演示。

演示只写入新的输出目录，不修改打包资源、旧模型响应、旧状态轨迹、评分、批准或发布归档。新目录中的演示记录与保存的历史研究运行分别保留。

## 如何理解它的证据

人工提案用来展示状态内核的行为，不能代表模型自行提取正确。唯一引文、可信角色、精确范围和条件校验可以发现结构不一致，不能证明自然语言含义被正确解释。页面中出现的结果不是模型准确率、真实成本测量或三方法排名。

预置提案、展示结果和本演示的输出只供讲解使用，不进入研究方法的请求白名单或工具环境，也不能当作额外人工状态加入公平比较。公开演示不改变原评测的输入隔离规则。

已保存 M1 影响证据来自此前的固定合成代码验证；本次只是读取该公开证据，不应描述为“这次重新执行了应用或补丁”。本演示也没有验证任意代码安全执行或真实自主回查。

研究进度另见 [S4 v8 开发比较公开摘要](s4/v8-development-closeout-20261109.md)。摘要从本地保存记录提炼，最新完整原始运行包与逐例审核原文未随本次演示整包公开。30 个开发案例参与过项目调试，参考由项目负责人确认，独立研究审核仍为 `not_performed_skipped_by_user`。本演示通过不会改变历史失败、评分或这些研究边界。

## 开发与贡献

优先改进文字、案例比较、键盘操作和来源展示，让读者能逐步解释结论。涉及新规则或新案例时，将人工输入、公开证据和计算结果分别标明；不要为让页面显示预期结果而修改旧原始记录。

安装依赖后，运行演示相关检查：

```powershell
uv run --offline --locked python -m pytest tests/test_demo.py -q
uv run --offline --locked writscope demo --output .work/demo-ui-check
node tests/demo-ui-smoke.cjs .work/demo-ui-check/index.html
```

也可在已激活的项目环境中运行 `python -m pytest tests/test_demo.py -q`。Node 脚本用最小 DOM 检查案例切换和键盘逻辑，不执行浏览器渲染；Node 仅用于开发检查，运行演示不需要它。再次生成时请换一个新目录。这些检查用于本次演示，不替代冻结研究版本的回放与发布检查；运行结果应以实际执行为准。

提交时保留已有用户改动，并让文档与命令参数一致。新增维护层应读取明确版本的公开数据，不重写历史 runner、源码哈希、提示词、响应、费用或参考。贡献和研究约定另见 [CONTRIBUTING](../CONTRIBUTING.md)、[数据契约](../specs/data-contracts.md)及[评测协议](evaluation-protocol.md)。
