# WritScope 研究方向与接下来的两步

日期：2026-10-20。性质：依据截至本日可核对的论文、作者项目及本仓库状态作出的**研究定位与工程选择**，不是新颖性证明或模型效果报告。交接书仍是初始需求；本文件收紧创新主张，不改变三轴评测、完整上下文清单强基线、同等证据和全成本核算。

## 大方向

WritScope 保持为**固定候选补丁的兼容性影响与用户授权范围复核研究工具**。核心问题是：在多轮要求、局部例外、撤销与重新授权之后，可重放的来源约束状态，能否比阅读同一完整历史的强清单方法，更可靠或更经济地判断**已验证代码影响是否被当前授权逐项覆盖**？

每次复核保持三个独立结果：`impact` 是代码事实，`authorization` 是当前有效用户许可的覆盖关系，`decision` 由二者组合；输出格式失败另列，不算作正确拒绝。工具反馈与代码注释只能提供事实，不能自行提升为授权。状态提取的语义错误必须计入方法失败；人工正确状态只作诊断。

首例 `status`→`state` 的三种历史是一个可复现的工程种子。**“同一操作、只变授权证据”的配对设计本身已被相邻研究采用，不能作为 WritScope 的新颖性主张。** 有潜力但仍待证实的组合是：执行验证过的具体代码影响 × 有来源和生命周期的授权更新 × 版本、字段、操作、条件的逐影响匹配 × 与完整历史清单同等证据、等配置和预算匹配的总成本比较。若强基线相当或更好且增量状态无成本优势，保留基准和负结果，收缩方法优越性主张。

## 与近期工作的边界

| 工作 | 已覆盖的能力 | 对本项目的约束 |
| --- | --- | --- |
| [AuthorizationPairs：Same Operation, Different Permission（2026-10-12）](https://arxiv.org/abs/2610.16838) | 固定操作、变化授权证据；语言轨 50 场景/200 上下文，含可执行效果，区分正确拒绝和无效输出 | 首例配对、可执行效果和误拦截拆分均非独有；后续需突出**持续更新的代码契约授权状态**和与强基线的成本比较 |
| [AuthGateBench（2026-10-12）](https://arxiv.org/abs/2610.16426) | 相同动作与轨迹、不同请求的授权反转；1,400 例，研究编码 Agent 的授权门控 | 不能声称首创“编码 Agent 授权对照”；WritScope 固定在**补丁造成的接口影响**与历史许可的结合 |
| [StateMemBench / StateMem（2026-08）](https://arxiv.org/abs/2608.19652) 与 [Supersede（2026-06）](https://arxiv.org/abs/2606.27472) | 事实/规则的现行状态、替代关系；显示状态维护与长上下文的差异 | “状态记忆”也不是新点；必须记录提取、维护、回查与复核的完整成本，不能把正确状态免费给增量方法 |
| [SWE-CI（2026-03）](https://arxiv.org/abs/2603.03823) 与 [Requirements After the First Edit（2026-09）](https://arxiv.org/abs/2609.03028) | 长期代码维护评测；真实编码会话中后到要求与返工的关联 | 说明动态需求有现实动机，但本项目的固定补丁实验不能外推为真实长期维护收益 |
| [AuthBench（2026-05）](https://arxiv.org/abs/2605.14859) 与 [AgentDojo](https://arxiv.org/abs/2406.13352) | 前者评测文件读写执行权限推断，后者评测不可信工具内容注入 | 工具权限与**用户是否允许某个破坏性代码效果**是两种边界；来源隔离仍是必要基础，但不构成本项目的全部目标 |

核对的作者/官方开源项目：[SWE-CI](https://github.com/SKYLENAGE-AI/SWE-CI) 提供长期代码维护基准，[AuthBench](https://github.com/evolvent-ai/Authbench) 提供权限生成与受限重放，[AgentDojo](https://github.com/ethz-spylab/agentdojo) 提供工具输出注入评测。[agent-memory-bench](https://github.com/GiulioDER/agent-memory-bench) 已包含 `superseded`、`contradictory`、`adjacent` 条件和检索/安慰剂对照；其当前公开运行自述为检索测试，并非完整记忆生命周期结论。这些项目用于校准设计，不作为现成代码直接并入，复用前另核对版本和许可证。以上是针对代表性工作的定位，不是穷尽检索，更不能据此宣布“首创”。

## 可检验的差异点

1. **影响与许可正交。** 同一破坏补丁在未授权和明确授权下，`impact` 保持 `breaking`，只有授权与决定变化；后续还需加入兼容影响对照，避免模型只学会“字段替换一定破坏”。
2. **范围与生命周期逐影响匹配。** 用户许可由可信事件和精确引文支持；v2 不覆盖 v1，允许新增别名不等于允许删旧字段，局部例外不撤销更宽约束；撤销和重新授权可从追加事件确定性回放。多影响补丁只有每项均被覆盖才能整体 `covered`。
3. **失败和成本可归因。** 将引文/结构无效、提取错误、状态更新错误、范围匹配错误与最终判断错误分开；比较必须保留完整上下文清单强基线、相同原始证据与基础模型，并把状态维护和失败重试计入总成本。

这些是**候选贡献与验收轴**。固定首例的代码影响和离线流程已验证；首次真实 DeepSeek 六任务均因旧引文位置契约无效，新 `source_quote_v1` 的独立真实开发运行得到 5/6 有效输出，见 [记录](m2b-quote-real-review.md)。没有方法胜出、成本优势或泛化证据。

## 技术栈定调

| 层 | 当前/下一步选择 | 理由与边界 |
| --- | --- | --- |
| 研究实现 | Python 3.12、项目 `.venv`、`uv.lock` | 沿用已验证环境；新依赖需有直接验收需求才引入 |
| 样例与验证 | FastAPI 合成应用、pytest、httpx `TestClient`、隔离副本 | FastAPI 是**被测样例**，不是要建立 Web 服务或产品后台；固定可信代码范围内执行 |
| 契约与状态 | Pydantic 严格模型；UTF-8 JSONL 追加事件/转换日志、可重建 JSON 状态、SHA-256 哈希 | 支持来源、决策时点、回放及可审计记录；先不引入数据库、图存储或向量检索 |
| 模型与成本 | 现有 provider 接口 + httpx；DeepSeek `deepseek-flash` 仅为已接通的**开发 provider** | 提示词、输出契约、模型响应、用量与估算均版本化；正式比较时同模型同证据并另行冻结配置，不将单一 provider 写死为研究结论 |
| 使用界面 | CLI、JSON/Markdown 报告 | 便于本地复现与开源审核；暂不增加 LangGraph、MCP、前端或 IDE/PR 集成 |

现有样例的文件白名单与副本不构成不可信代码的操作系统沙箱。若将来开放任意候选执行，必须先单独设计权限边界；这不进入接下来的两步。
