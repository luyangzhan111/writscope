# c004 局部映射提取失败：离线诊断与候选修订

日期：2026-10-26。本步只处理用户已授权的离线排查；新增真实模型请求为0，不读取密钥，不变更任何冻结真实工件。

## 根因

v4 保存的 c004 `e001` 响应先正确抽取了 `status` 服务端契约约束，也把整句“可以在客户端本地映射成页面需要的 state”保存在任务背景；但同时从同一句再生成了授权：主体指向服务端响应 `field=state`，操作为 `add_alias`，旧字段为 `status`，并引用 `status` 约束。

这不是输出 JSON 形状错误：响应通过 interaction v3 的结构、引用和当前事件来源检查。错误在语义层把客户端层的实现选项提升成服务端 API 权限。随后范围内核正确拒绝：授权主体字段与 `old_field` 不一致，且所引用约束的范围不匹配。原子状态没有提交，运行器按首次失败停止。旧版本明确写了禁止规则，但模型没有遵守；因此根因不是提示词缺少这条规则，也不能声称仅增强提示词就已修复模型。

## 离线处理

- 新增通用候选提示词 [interaction v6](../prompts/incremental_interaction_v6.md)：先判定陈述所治理的组件层；grant 必须有当前可见的可信用户语句明确许可服务器/API 可见范围变化；客户端本地展示/映射作为任务背景，不得推导授权，也不能借用未来事件的许可。
- 新增三项离线控制：v6 文本边界检查；原保存响应仍在现有解析器通过、在原子状态引擎以相同范围原因拒绝且不提交；人工构造的结构控制把同一事件表示为“本地映射任务背景 + 旧 API 契约约束、无授权”，并通过现有解析和原子状态引擎。该人工控制证明这种表示在当前管线可提交，不是模型输出、参考答案、模型能力证据或独立标签。
- v4 原响应和拒绝不修补、不重写、不继续；真实失败及调用账本仍可追溯。v4 运行器、冻结计划和 v4 提示词均未修改。v6 只是未接入运行器的离线候选版本，不能用于旧计划或旧授权。

针对性测试 **3项通过**，覆盖以上提示规则、原保存响应的确定性拒绝及人工结构控制；没有模型调用，故不能知道模型是否会遵守 v6。范围内核继续作为独立防线，任何错误授权仍须拒绝并保留失败。复核时原真实运行的 calls/jobs/run 哈希分别为 `1c96eb88004985bed3d049a70af76418e3c0490922e820ee3a347a1f360265d1`、`ba7e1c0dea7ff22666a6b61015025440f7b3ac8d0e59b77d7e5ce9d3cd16c932`、`0664456d6c73c5f78a57b109eebe3b4373fc7eb00958fc7abcecc99d44aee7c3`，与既存收尾清单一致。之后已按该结论完成离线评审并冻结新单轨候选，见 [v5 预检](s3-development-v5-preflight.md)；计划未授权，真实模型行为仍待验证。不能复用已用的6元授权或把同一案例的模型输出当作未见样本。
