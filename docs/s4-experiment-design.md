# S4-A 正式比较设计候选

2026-10-28。用户已选择比较 **R=3**，并要求当前 S4 跳过无法完成的独立审核。后续范围为**项目内审核的开发比较**：项目内逐例语义审核仍待进行，独立审核记为未执行，不得宣称独立验证。完整方案仍是**未冻结、未批准草案**，不授权读取凭据、发送材料或调用模型。当前 P2/P4 运行器只能使用脚本 provider；真实模型入口、正式评分报告和数据冻结均未完成。30 例均为开发/试验数据，比较结果即使以后产生，也不能直接证明对未见场景泛化。

## 比较范围和建议配置

主候选为 A 轨：所有方法获得相同原始证据、固定候选、公开契约、已验证影响和同等只读回查权限；不向方法提供参考标签、人工状态或兼容参考解。

| 方法 | 流程 | 设计要求 |
| --- | --- | --- |
| `full_direct` | 完整历史直接复核 | 不截断必要历史或影响证据 |
| `full_checklist` | 完整历史重建清单再复核 | 核心强基线；保留足够上下文和输出空间 |
| `incremental` | 逐事件提取并维护状态，必要时回查，最后复核 | 从空状态开始；提取、状态更新、回查和终点的全部成本计入 |

用户选择主比较每例每方法 **R=3**；三个重复不增加独立场景数。模型可用性、预算与完整方案仍需单独核对并获得授权；这一选择不批准调用或费用。若需要真实接通检查，建议仅用此前四例、每方法一次，另立开发试跑计划、预算和材料外发范围；它不能与之后的正式比较拼接。

当前 P2 离线策略允许每轨至多 3 次回查，且每个阶段至多一次续答、无自动重试。30 例共有 **126 个事件**；按当前每阶段上限计算：

| 范围 | 计划轨迹 | 最大 provider 尝试 | 说明 |
| --- | ---: | ---: | --- |
| 可选四例接通试跑，R=1 | 12 | 52 | 另立计划，只用于接通检查 |
| 一轮，R=1 | 90 | 360 | 两种基线各最多 60 次；增量最多 240 次 |
| 已选设计方向，R=3 | 270 | 1,080 | 以上上限乘 3，非批准调用数 |

每种基线每例有一次终点和最多一次回查续答；增量每例有 `事件数 + 1` 个阶段，最多再加 `min(3, 阶段数)` 次续答。上限不等于必然调用数，未触发回查应记未触发，不能强制触发或补跑凑结果。如果提示词、工具权限、阶段、重试或事件数量变化，须重新计算。机器计算明细见[设计草案](../evaluation_private/s4_review/experiment-design-candidate.json)。

本轮早期草案曾把可选接通试跑写成全批 R=1；为限制试跑范围，当前候选改为此前四例。早期草案[另存](../evaluation_private/s4_review/experiment-design-earlier-draft.json)，未获批准、未运行，也不代表正式方案。

用户的 R=3 选择和独立审核者暂缺已在[独立决策记录](../evaluation_private/s4_review/user-design-decision.json)中绑定原候选计划哈希；选择前的文档及校验清单保留在同目录的 `pre-decision-snapshot/`，不追改原实验草案。

用户随后明确跳过当前 S4 独立审核，另存[跳过决定](../evaluation_private/s4_review/independent-review-skip-decision.json)和[更新后的设计候选](../evaluation_private/s4_review/experiment-design-after-skip.json)；先前草案和决定保留。用户逐例语义审核没有因此自动完成，S3 独立研究验收状态也不变。

所有方法应固定同一基础模型及实际版本、温度、可用推理设置、原始证据、工具权限和外部服务条件；建议温度 0 作为待验证候选，模型、版本、输出/上下文上限、随机顺序与种子仍未确定。冻结前须验证完整清单基线不会因截断而失效。按预先固定的、与标签无关的顺序规则安排方法和案例，记录实际顺序及供应商版本；不能在看到结果后选择有利重复或排除困难任务。

## 指标、失败和成本

按[评测协议](evaluation-protocol.md)分别报告 impact、authorization、decision、三轴同时正确、成对正确、误放行、误拦截、歧义处理和无有效输出。主授权指标以**参考为 breaking 且授权非争议的计划任务**为分母，不能按模型自己的 impact 筛选。争议案例的处理规则和各分母须在看真实结果前冻结，争议结果单独报告；失败和未运行保留在对应计划分母，不伪造 `revise`。

先做等配置比较并分别报告每种方法的实际全程成本；预算匹配比较应是**单独的实验块**，事先规定共同预算、截断/停止规则、失败处理和计划分母。不能从等配置结果中事后挑选费用接近的成功轨迹冒充预算匹配。质量相近容忍、误放行/误拦截容忍和成本收益判据目前均未确定；未冻结时只允许描述性结果，不能声称达成某个优势门槛。

每次请求的发送前预留、实际响应、输入/输出及缓存 token、回查续答、终点、失败、重试、本地更新和验证时间均须记录；缺失项为 unknown。按冻结时的实际材料大小、上下文/输出上限、官方新鲜价格、币种与汇率估算最坏支出，先约定全轮停止规则，再请求独立预算与精确材料外发授权。现阶段没有核价，不填费用；本地预留也不等于供应商硬账单上限。

## 冻结前必须完成

- 完成或明确记录 [P3 语义争议](../evaluation_private/s4_p4/disputes.json)，取得项目内实际审核结论；当前独立审核已由用户跳过并记为未执行，不作独立金标准主张。数据、参考、分歧处理和配对划分须有版本与哈希。
- 另立真实 provider 入口、授权/一次性启动闸门和独立真实评分器；目前 `score_real_only` 明确未实现，P4 模拟脚本及报告不能被当作真实实验。
- 决定并测试 P2 当前增量终点与结构状态不一致时标为无效的策略；这会影响失败率与方法公平性，须在正式比较前固定，不能事后根据成绩选择。
- 拟定并核验各方法实际提示词、结构契约、模型设置、真实输入白名单及账本。P2 的英文短提示是脚本接线占位内容，尚非可用于正式比较的冻结提示词。
- 确定模型/R/上下文和输出限制、排序、所有阈值、等预算块、停机和故障处理；核对官方价格及完整最坏预留，明确将发送给谁的具体公开材料，再按精确计划申请新的费用和外发授权。
- B 轨须另建并验证独立执行权限边界；目录副本和白名单不等于操作系统沙箱，当前不开放任意 shell/Python。

以上任何一步的草案、人工检查或脚本演练都不构成实际付费运行授权，也不提升 S3 的独立研究验收状态。
