## 1. 目标与起点

S4 要交付一套可重复的受控比较：在同一批原始证据、基础模型和工具权限下，观察增量授权状态维护与完整上下文直接复核、完整上下文清单强基线的质量和全程成本。

当前已有有限开发场景的 S3 作者审核验收、真实回查链、保存后回放和成本记录。S4 的 P3 已补充 30 例输入和八套合成代码变体；P4 已完成三方法 90 轨离线脚本演练，不代表模型成绩。v8 入口固定 c004，旧共同运行器固定三条开发历史，不能代替 S4 新入口。独立审核仍缺，S4 真实比较未运行。

第一目标是完成 **S4-A 离线评测准备**，作为下一次有实质功能进展的 GitHub 更新。随后在新冻结与新授权下执行 A 轨；B 轨按单独权限门槛推进。A 轨完成不自动代表整个 S4 或完整独立研究验收完成。

每个应用的六个配对变量沿用既定协议：明确授权、API 版本、变更操作、作用对象、撤销/重授、局部任务压力。每对固定代码、候选、公开契约和影响事实；仅改变相应授权变量，记录必要差异。

首例内容纳入对应配对，不额外累加为 33 例。c004 已参与反复调试，不直接增加为独立未见样本。后文的 4 例小切片从这 30 例中选取，不额外扩充样本数。

每例必须具有：中性 ID、家族/配对/用途映射、决策时点、完整原始事件、可信角色、固定候选、公开契约与影响证据、评测器侧参考及依据。家族、配对和答案元数据不得因方便而全部暴露给方法。成对变体不能跨集合，重复采样不增加独立场景数。

## 4. 工程实现原则

### 数据、运行、评分分离

- 案例清单驱动输入，移除对 c001/c004 的固定任务选择依赖；同一配置服务所有实例，不为失败案例另写提示词分支。
- A 轨给三方法相同、已核验且不含授权答案的影响事实。完整上下文清单基线保持完整历史和足够输出空间；增量可按冻结策略回查相同截止点前的历史，阶段可见性差异需要披露。
- 方法仅接收白名单输入；参考标签、人工状态、兼容参考修复、隐藏测试、其他方法响应和未来事件留在评测器侧。角色权威来自可信导入器，工具事实不能自升为用户许可。
- 模型调用和状态更新完成后，独立评分器才读取参考。歧义、语义错误、解析失败和无有效输出分别记录；失败不能自动生成 revise。

### 保留历史可复现性

优先增加独立 S4 入口和版本化配置，复用已核验组件，保留所有 S3 负结果。当前 `_code_provenance()` 会散列整个 `src/writscope` 的 Python 源码；即使只添加文件也可能改变旧预检。P0 必须先设计该版本边界：优先让新入口在既有依赖不变的前提下工作；若必须重构，则先保存旧源码/环境快照并验收版本化回放，不跳过或放宽旧哈希校验。

旧提示词、冻结规格、标签、授权收据、一次性 claim 和费用不改。新工作使用新目录和计划标识，不能沿用已消费的许可或把模拟工件升级为真实运行。

### 故障和成本

推荐草案为单并发、无自动重试；正式值在 P5 冻结。一般模型/schema/状态故障停止当前轨迹，保留失败后处理其余计划任务；数据污染、隔离/哈希失配、总预算越界等完整性故障停止全轮。连续服务故障的停止阈值也须预先确定，不临时改规则求完成。

提取、任务背景/状态维护、回查续答、终点复核、验证及失败尝试全部对账。共享影响证据制作与人工审核成本单列；未知费用、推理 token 和人工耗时保持 unknown，不能记零。对外的本地预留上限不冒充提供商硬账单上限。

## 5. 离线验收清单与下次 GitHub 更新

P4 达标后，公开更新为“30 实例开发评测集与三方法统一离线入口”。必须同时具备：

1. 完整的 30 例及两应用代码、公开契约、候选和可核验影响事实；12 对的受控变量检查通过。
2. 输入包与评测器材料分离；未来/未知引用、路径越界、工具伪授权和参考哨兵泄漏等检查有效。
3. 三方法全批脚本演练，另有故障控制；所有新增演练保存后可重建，待运行报告保留全部任务。
4. 成本总账、失败分母、语义错误和运行失败分开；脚本运行的模型指标为 null，不宣称真实模型效果。
5. 旧 S3 代表性成功/失败记录仍可复现；新增入口不破坏原先公开演示。
6. 使用说明、局限和冻结草案齐全；相关检查通过后再同步功能里程碑。

离线演练可以先固定 R=1：30 例 × 3 方法 = 90 条轨迹。轨迹数不等于请求数；增量轨迹有多事件提取、回查续答和终点。模型正式 R 仍待预算与稳定性目标确定，不能将这次离线 R 自动变为真实运行批准。

开发过程可保存小提交；文档纠错与必要修复无需等到 P4。当前规划先留本地，不将纯规划更新包装为已实现的评测功能。

## 6. 真实运行前必须解决的事项

| 待决项 | 冻结要求 |
| --- | --- |
| 模型与 R | 基础模型/实际版本、温度、可用推理配置、输出和上下文上限、重复次数、顺序/种子及缓存策略；不能截短强基线来使其可运行 |
| 质量与错误阈值 | 授权主指标、质量相近容忍、误放行/误拦截容忍及成本收益判据，在看本轮结果前确定；未确定时只作描述性报告 |
| 等配置和预算匹配 | 两种实验单独计划、执行与汇总；相同模型不等于相同总预算，不能事后挑成本接近的成功记录配对 |
| 费用与发送范围 | 根据实际请求大小、最大输出和调用上界核价；批准确切计划/源码哈希、总额、调用数、停止规则及发往指定 provider 的材料清单 |
| 参考审核 | 记录作者审核、实际独立审核和争议状态；脚本或另一代理不能自动计为独立审核 |
| B 轨权限 | 需先建立和验证独立的执行权限边界；仅复制目录或文件白名单不构成 OS 沙箱，不向方法开放任意 shell/Python |

单个 A 轨实验配置包含 `30 × 3 × R = 90R` 条计划轨迹。若两条基线各一次请求、每例有 `N_i` 个事件、最多 `L_i` 次续答且无重试，则最大请求量可按 `R × Σ(2 + N_i + L_i + 1)` 估算；实际阶段定义及失败预留由新运行器核验。预算匹配块与 B 轨额外计算，不藏入同一统计表。本计划不填未经核对的价格或金额。

如需要小型真实接通检查，应在正式比较前单独冻结并授权，记录为开发试跑；后续改提示词、规则或数据时另立版本，不能把该试跑拼入新版本结果。无自主回查仍如实记 not_exercised，不强制触发或补跑凑成功。

## 7. 报告与收尾

报告沿用协议：分别呈现 impact、authorization、decision、三轴同时正确、成对正确、误放行、误拦截、无有效输出和歧义处理；按应用、变量、方法和重复拆分。统计分母由参考和全部计划任务确定，不能由模型自己的判断或成功状态筛选。

错误分析区分影响理解、语义提取、生命周期、作用范围、条件引用、终点组合及运行故障，允许多标签。报告每阶段费用、用量、耗时、失败成本与 unknown；作者审核和有限开发样本的限制保留。

A 轨的完成条件是冻结范围内真实记录与可重算报告齐全。完整 S4 按现有协议处理 A/B 与全部退出条件；任何未执行部分明确列为未运行，独立审核不足不消失。若强基线相当或更好，或增量的额外调用没有形成成本收益，则保留负结果并收缩方法主张，后续工作转向误差归因与评测框架价值。
