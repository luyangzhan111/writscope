## 本次实现

- [模拟闸门](../scripts/s4_r3_mock_gate.py)绑定计划、公开包调度、模拟脚本、相关源码及虚拟预算；受测对象为 `mock.invalid`，材料范围限定为公开合成输入。运行前重新生成计划并核对绑定、有效期、限额和范围。它只接受明确标记为 `synthetic_test_fixture` 的测试材料，拒绝以 `approved=true` 或自报角色作为真实用户批准。这个测试材料和模拟 claim 都不是正式授权证据。
- 验证通过后，用独占创建的本地文件记录一次性模拟启动，写入并刷新后才进入模拟运行；竞争启动只能有一个成功，中断不释放 claim。失败的前置校验不创建 claim。该机制仅在当前本地文件系统的测试条件下演练，不声称跨机器、不可篡改或满足正式审批审计。
- [逐轨模拟运行接口](../scripts/s4_r3_mock_runtime.py)复用现有调度、执行、固定 `httpx.MockTransport` 和单 SQLite 账本；各轨完成后立即持久化轨迹，保留同一账本的发送前预留、发送开始、响应和验证记录。完整计划分母包含未运行项。回放检查计划及源码绑定、轨迹次序、分母、请求字节、续答标记和已完成响应对应关系；不是独立状态机或来源认证。
- 既有 [R2 入口](../scripts/s4_unified_offline.py)、账本及历史哈希绑定工件保留。新接口以一轨调用已有执行器，生成自己的版本和绑定，不能与旧 repeat 结果视作字节相同；此版只支持离线 mock，正式公平比较仍须审查方法配置及证据一致性。
