# S4 R3 模拟 provider 与中断核对补充

2026-10-30。此项为 R3 和 R2 的离线补充，**真实发送仍关闭，R3 联合验收仍未完成**。未读取真实凭据、未联网调用模型、未外发材料、无新增费用。独立审核按用户决定为 `not_performed_skipped_by_user`，不代表通过。

## 已实现

- [模拟 provider 边界 v1](../scripts/s4_r3_provider_mock_v1.py)只接受固定 `https://mock.invalid/chat` 和本地合成响应，由函数自行创建 `httpx.MockTransport`；调用者不能注入真实传输。复用 R2 的 SQLite 账本，先持久化预留和发送开始，再保存响应原始字节及哈希，最后保存校验结果；模拟超时保留预留和未知用量。重定向、非固定地址、截断、无效响应及输出大小超过限制均拒绝；原始模拟响应在拒绝前保留。实际 provider token 与账单均为 unknown。大小限制在完整响应已被读入后执行，并非网络流式硬上限。
- [逐轨中断只读核对](../scripts/s4_r3_mock_recovery.py)为现有 R3 逐轨运行格式重建计划分母，校验计划、调度、脚本、源码及账本绑定，区分未决尝试、已保存但未验证轨迹、已发送但轨迹未知和无尝试且轨迹未知。不修改原始工件，不自动续跑，也不宣称恢复未写入的状态、回查或终点。
- 旧运行器、R3 模拟入口和历史工件的受绑定文件没有改写。新的 provider 边界目前独立接到同一账本，**尚未接入 R3 逐轨运行器**；单次适配器测试不能代替整条轨迹的联合验收。

## 验证

定向执行 `tests/test_s4_r3_provider_mock_v1.py`、`tests/test_s4_r3_mock_recovery.py` 和 `tests/test_s4_r3_mock_gate.py`，**25 项通过**。测试包含固定地址拒绝、模拟重定向、截断、大小、错误原文、超时、发送前后及响应落盘后的持久化故障，逐轨写入失败后的分母核对、未发送预留的未决状态、计划篡改和两个进程竞争模拟启动。所有响应均为合成材料；结果不是提供商真实性证明或模型成绩。

## 后续联合验收和实际授权接口

实际执行前的正式计划必须绑定公开包、提示词和 schema、执行源码与依赖、模型及配置、服务商与地址、价格来源与有效期、最大请求数、预算币种及上限、逐项外发范围、停止条件和计划哈希；正式批准必须由能核验用户身份与原始批准内容的可信会话或审批系统关联该精确计划。仅提供 JSON 中的角色、`approved=true`、自写收据或内容哈希不够。**当前没有实现可验证实际用户批准的可信接入，也没有创建正式批准收据；测试 fixture 不能升级为授权。**

仍需完成：将版本化 provider 边界安全接入维护入口；在单轨执行期间对回查、状态转换与终点逐项持久化并测试中断窗口；将本地更新、回查和验证耗时接入成本契约；对真实计划的价格和授权证据实现可信核验；以独立评测器和全批完成 R4/R5 联合离线验收。当前只完成部分模拟接口和故障核对，不能据此声称 R3 或全部 R2 缺口已完成。数据语义确认和冻结另行处理；即使联合离线验收通过，也必须针对具体计划另获预算及外发授权，不能自动开启真实发送。
