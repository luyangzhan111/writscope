## 推荐顺序与验收

| 顺序 | 工作包 | 交付和完成条件 | 依赖 |
| --- | --- | --- | --- |
| R1 | 项目内语义与方法口径收尾 | 对 30 例、12 对和争议给出可由负责人确认的简明决策表；明确歧义/分母、增量冲突和比较范围。实际确认前保持 provisional | 现在可做；确认只阻塞最终冻结 |
| R2 | 统一执行内核、记录与预算 | 选择一个维护入口，统一任务/阶段/原始响应/状态转换/成本。预留、发送状态与结果有可核查持久化关系；双库合并或证明故障协议闭合。中断后停止且可审计即可，不要求自动续跑 | 沿用 R1 暂定策略即可实现 |
| R3 | 授权、一次性启动与传输边界 | 精确计划与实际用户批准证据关联；凭据读取前拒绝未批准、旧授权和范围不匹配；一次性启动；provider 适配在固定模拟传输下测试，真实发送保持关闭 | 先约定 R2 接口，再接线 |
| R4 | 独立轨迹验证与正式评测候选 | 不依赖与旧 mock 结果相等；从保存的执行记录重建、检查来源与状态，再读私有参考。输出三轴、缺失/歧义/配对/误放行与误拦截、原始分子分母和完整成本 | R2/R3 的记录及来源接口稳定 |
| R5 | 同一版本的联合离线验收与交付 | 正常全批、金额/次数不足、普通故障、完整性故障、中断及篡改，用同一入口和评测器验证；旧成功/失败代表性回放、无密钥演示及交付恢复检查通过 | R2–R4 完成；R1 可仍待确认 |
| R6 | 冻结候选与具体授权方案 | 确定数据/参考/策略/提示词/模型/顺序/限制/判据，重新核价并给出准确发送清单、最多次数、费用与停止规则；保留待批准状态 | R1 得到确认或明确记录最终争议处置；R5 通过 |
| R7 | 专项授权后的真实试跑与比较 | 只执行人类针对具体新计划批准的范围；保存失败和全部分母；可选四例试跑与正式比较分别授权、分别报告 | R6 完成，实际取得对应预算和外发批准 |

实施主线是 **R2 → R3 → R4 → R5 → R6 → R7**；R1 尽早整理，负责人确认前可继续独立离线工作。这里是依赖关系，不要求建立并行子代理或新聊天。

### R2–R4 必须具体解决的接口问题

- **记录**：按 `(case_id, method, track, repeat_index)` 固定任务；每次 attempt 单独标识，保存实际请求字节、响应原文/错误、起止时间、finish reason、回查及续答、状态更新与终点。未知状态不能合成成功或 revise。
- **成本**：包含失败、提取、续答、终点、缓存/reasoning token、本地更新/验证和共享证据制作成本。币种、费率来源、估算/账单分开；缺失保持 unknown。字节代理尚未证明为提供商 token 上界，不可称硬费用保证。
- **故障**：普通 provider/schema/状态错误停单轨；计划/来源/隔离/账本和额度故障停整轮。未预留/未发送不虚增尝试，已发送后超时或中断仍保留尝试和预留。错误类型和连续服务故障阈值预先确定。
- **来源与授权**：哈希只能核对一致性；自填 `approved=true`、`real_model` 或角色字段不能证明批准或真实来源。记录实际能验证的证据，不能承诺没有服务商证明的真实性认证。凭据不进入工件或报告。
- **公平性**：保留完整上下文清单强基线；增量当前终点看完整历史加维护状态。三方法相同原始证据及权限。终点/状态冲突保留合法原终点作为预定义诊断，主输出仍按冻结规则失败。
- **引用质量**：结构/精确引用/角色/截止点检查与“引用是否语义支持判断”分别报告。后者若仍无实际审核，记未评估，不能把语法合法率改称语义准确率。

### R5 与 R6 的范围约束

不再扩充案例、不新增压缩历史方法、不开放 B 轨任意代码执行。优先统一现有能力；不要每轮另建一套功能相同的模拟运行器。受哈希绑定的旧脚本/记录保留，新维护入口必要时另立版本并列出迁移关系。

R5 的 270 条正常轨迹应由新统一入口实际生成；657 是旧固定脚本的观察数，不能硬编码为所有运行都必须满足的成绩。1,080 仍只是当前规则下的设计上界，要按最终阶段/回查/重试规则重算。模拟可验证计算算法，面向项目的结果报告继续明确模拟，不发布模型准确率。

主块建议先做等配置比较；预算匹配必须单独预先设计，不能事后拼成功轨迹。若暂不做预算匹配，冻结文档明确后置，不能把它静默算为已完成。未决定优势阈值时，只允许描述性分析；不以好成绩为验收条件。

四例 R=1 接通试跑可选，不是自动追加的前置实验；主比较 R=3 已选方向，但尚未获运行授权。真实试跑与正式主比较必须区分批准范围，不拼接成绩，旧 S3 额度不可复用。
