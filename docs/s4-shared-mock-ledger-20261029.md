# S4 共享虚拟账本与执行中模拟传输

2026-10-29。新增[共享账本适配](../scripts/s4_shared_transport_offline.py)、[候选运行器变体](../scripts/s4_candidate_shared_mock_runner.py)和[重复调度](../scripts/s4_shared_repeat_offline.py)。三种方法和多次重复在运行过程中使用同一个 SQLite 账本：每次内存模拟传输前持久化虚拟额度预留、请求与合成响应，并标记模拟发送；保存模拟结果后才结束该条预留。源码和计划绑定到该离线运行。模拟响应事先来自固定脚本，它不是服务商返回的响应。

单案例测试覆盖三方法、全部事件与终点、回查续答、R=3、预算耗尽、普通模拟故障停单轨、完整性故障停全轮、账本中断未决、篡改拒绝和重开账本核对。相关测试分批执行，合计 11 项通过，其中含既有账本与重复调度回归。账本中缺失用量和实际账单保持 unknown，不计为零。离线失败测试的 503 仅是脚本故障的合成占位，不能当作真实 HTTP 故障原因。

30 例、三方法、R=3 的[低虚拟额度演练](../evaluation_private/s4_review/s4-shared-budget-check-v2.json)保留 270 个任务，1 完成、269 未运行，2 次模拟尝试使用了同一账本；保存后重开账本核验。此前 v1 是后续源码调整前的中间记录，原样保留，最终演练使用 v2。

正常[全批演练](../evaluation_private/s4_review/s4-shared-full-check-v1.json)使用虚拟上限 1,080，实际 657 次虚拟预留、270 条脚本轨迹完成，含 9 次脚本回查；保存后重开账本核对逐次请求、合成响应及结果。该计数不代表真实调用。全批运行与既有脚本轨迹逐项一致；[评测接线](../evaluation_private/s4_review/s4-shared-full-metrics-check-v1.json)只在共享工件与既有脚本核验之后读取评测器参考，仍不发布模拟分数。

执行记录保存在评测器侧，逐次账本和响应在被 Git 忽略的 `reports/local/s4-shared-full-20261029/`；需保留本机目录或用同一源码和公开输入重建。其哈希只能检测不一致，无法证明用户授权、真实来源或防止整套数据被共同改写。此验证重放传输和账本、并与旧脚本逐项对照，不是可信真实运行验证。

仍需完成：可信且可核查的真实授权及一次性启动、真实发送前预算/价格约束与完整费用、真实传输的原始响应和中断恢复、正式评测与来源验证。当前模拟预算仅按次数，不是金额上限；进程中断时账本保留未决尝试，但不实现自动续跑或完整中途任务记录恢复。方法输入及工具未获得任意代码执行权限。正式数据和项目内逐例争议仍未冻结；独立审核按用户要求跳过，记未执行。未读取真实密钥、未发起真实模型请求、未外发或产生模型费用。
