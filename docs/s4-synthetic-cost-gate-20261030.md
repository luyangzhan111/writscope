# S4 虚拟金额预留离线验证

2026-10-30。新增[虚拟金额账本](../scripts/s4_synthetic_cost_ledger.py)、[模拟传输预算接线](../scripts/s4_synthetic_cost_wire.py)、[成本候选运行器](../scripts/s4_candidate_cost_mock_runner.py)和[重复调度](../scripts/s4_synthetic_cost_round.py)。它以合成输入费率、输出费率、帧开销和输出上限计算每次保守取整的虚拟预留；账本用 SQLite 事务串行分配，失败、缺失用量和中断不释放已有预留。两份账本之间发生中断时，金额账本保留未决状态并阻止后续预留。

预算入口先根据完整模拟请求计算 wire 字节，再执行预留及固定内存 MockTransport。相关测试核对虚拟预算使用的 wire 哈希与模拟传输一致；次数、计划/价格口径绑定、并发、中断、篡改、金额不足和三个重复均有检查。金额不足且本次尚未预留和发送时，计划任务保持 `not_run`；若同一任务已进行过尝试，后续续答因预算不足被阻止，则该轨迹记失败，并保留先前尝试。

18 项定向和回归测试通过。另做[30 例 R=3 虚拟额度演练](../evaluation_private/s4_review/s4-synthetic-cost-budget-check-v1.json)：完整计划 270 条，1 条在首次模拟回查之后因额度耗尽而失败，269 条未运行；共 1 次模拟尝试，25,055 虚拟微单位预留，重开两个账本后核对通过。这个数字是故意构造的虚拟单位，**不是人民币、实际定价、费用估算或授权**。没有真实模型调用、实际密钥读取、网络外发或真实账单。

当前实现仍是离线原型：价格是合成值，按 wire 字节加帧开销估计输入 token 是未验证的保守代理，不能保证实际提供商 token 上界；本地预留也不是提供商硬账单上限。金额与模拟传输是两个账本而非跨库原子事务；中断后禁止自动继续，不支持完整恢复。当前演练没有运行 270 条完整金额模拟轨迹，也未将它接入真实 provider 或正式评测器。文件哈希、人工创建的 JSON 和测试凭据都不能证明真实授权、材料外发同意或运行真实性。

后续仍需真实计划的模型与价格、预算和外发范围具体冻结并取得专项授权，建立可信凭据读取前检查、一次性启动、真实请求/响应与完整成本账本，验证全轮故障和正式评测。30 例项目内语义与争议处理仍待确认；实际独立审核按用户决定跳过，状态为未执行。
