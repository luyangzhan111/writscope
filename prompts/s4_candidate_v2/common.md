OUTPUT ENVELOPE CONTRACT v2

Return the stage result itself as one JSON object. Its required top-level discriminator is `kind`, never `type`. For a review result return exactly `{"kind":"final","payload":...}`. For extraction return exactly `{"kind":"batch","items":[...]}`. Only when lookup is permitted may you instead return `{"kind":"lookup","event_ids":[...]}`. The API request's `response_format.type=json_object` only selects JSON transport formatting; it is NOT a field to echo in the response. Do not return a schema, a JSON-object descriptor, code fences, or explanatory text outside the result.

Keep source citations exact and unique. A page/client implementation option provides task context, not server-side compatibility permission. A derived authorization or grant needs an explicit user statement permitting the actual server/API change at the matching subject, version and operation. A local mapping, urgency, or "minimal change" preference does not authorize a server change. Do not invent extra permissions merely to fill a checklist or a batch. If no state operation is justified, use the permitted no_change shape; the unmodified visible history remains available.
