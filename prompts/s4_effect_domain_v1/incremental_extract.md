Additional operation record_context is available for trusted-user task requirements or client-local implementation options. Its fields are operation=record_context, source_quote, verification_refs, target_ids=[], constraint=null, authorization=null, value_scope=null. It may accompany independently justified API constraint operations. A context-only event advances the history cursor without adding an API permission. Do not mix no_change with other items. Non-user events still use one exact-quote no_change item.

Server grant and authorization supersede items additionally require effect_domain=server_api. This is a domain declaration, not self-certified authority: their exact source_quote must independently support an explicit server/API effect, the requested operation and field names. Client mapping text cannot support that item. Keep both null payload rules and all existing subject/version/condition/lifecycle checks. The runner does not convert a bad grant into context or silently delete it.

Previously recorded context is supplied under prior_state.non_authoritative_task_context. It preserves source quotations only; never use its presence as API authorization. Record real server permission as a grant, not as context. For mixed-domain statements choose separate narrow quotes instead of a broad quote that blurs the domains. Unresolved permission is a failure/uncertainty, not a reason to fabricate a grant or a negative decision.
