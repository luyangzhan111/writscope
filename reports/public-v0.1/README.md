# 首次公开版精选证据

本目录包含 `evidence.zip` 和逐文件 `manifest.json`。归档保存 359 份历史文件，原始内容约 12.2 MB，压缩约 2.1 MB；包含 v8 成功、v7 终点失败、九任务共同覆盖，以及测试/冻结运行器所需的前序证据、旁存源码与脚本控制报告。全部为开发材料，包含合成案例、作者审核、模拟与真实运行，不能视为独立样本数量或统一方法比较。

本次整理的实测见 [validation.json](validation.json) 与 [tests](checks/pytest.txt)；原始候选提交 `1a7d412` 的文件校验见 [source-manifest.json](source-manifest.json)，后续发布说明不在该历史快照内。历史归档清单与本次整理验证分别保存。

## 恢复和使用

在仓库根目录执行 `uv run --locked python -m scripts.public_release restore`。工具先核对压缩包与逐文件 SHA-256、路径和全部现有文件冲突，再将文件恢复到被忽略的 `reports/local/`。相同内容可重复恢复；任何内容冲突均停止，不覆盖工作区。

- `demo`：新建无密钥脚本演示；真实调用始终为 0。
- `replay`：重建保存的 v8 成功、v7 失败和旧九任务覆盖，生成新作者审核报告。历史调用数与本次新增调用数分别记录。
- `audit`：扫描候选源码、Git 历史 blob 和解压后的证据内容。只报告匹配类型和路径，不输出疑似凭据。

## 原件、迁移与权限

归档按历史相对目录保存原件；原始内容未脱敏改写，保持原哈希。已扫描常见凭据模式，未发现匹配；模式扫描不是无敏感信息的数学证明。历史日志可能含本机路径、冻结 API 地址、模型 ID、成本和已消费授权的文字收据。这些信息为复现明确保留；不含 `.env`、虚拟环境或实际 API 密钥。

冻结 verifier 的启动检查要求原机器绝对路径。`replay` 先验证归档，检查原收据与已保存运行的计划/授权标识，再仅在内存中把启动输出路径定位到当前目录。转换逐项写入新的 `portable-replay.json`；原收据、原评分、预算、请求和响应均不写回。v7 终点错误摘要 `null` 仍按原记录保留；失败原因另见原诊断文档。

该适配不更改范围校验、提示词或状态逻辑，不跳过计划/源码/请求/结果/费用复算。它不创建 approved 凭据，不授予发送数据或支付费用的权限；保存的旧授权不能复用。

## 范围

清单依据历史测试与运行器的静态依赖、明确代表性证据及引用闭包选择，不是完整 `reports/local/` 备份。未选择的临时测试目录、重复演练和调试目录仍保留在原机器。源码/锁文件/冻结提示词变更后，某些历史 verifier 应拒绝哈希不一致；不要为使其通过而重写清单。

`evaluation_private/` 和作者答案属于评测器侧；本归档及项目文档整体不得作为被测方法输入。方法输入仍必须由既有白名单生成。公开仓库可访问性与运行时模型权限是不同边界。
