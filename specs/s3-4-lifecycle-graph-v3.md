# S3.4 生命周期图对齐 v3

日期：2026-10-25。实现：[s3_4_lifecycle_alignment.py](../scripts/s3_4_lifecycle_alignment.py)。这是评测器侧结构诊断，不修改 v2、状态内核、模型契约或历史评分。

## 输入与信任

入口先完整复验已保存的语义/生命周期边界审核，再读其六个合成分支、批次日志与状态。每条原批次重新在原 M3j/M3f 引擎执行并核对记录；每个已保存扩展状态必须与重建状态相同。另按固定一一映射改名约束/授权 ID，连同目标、约束引用和替代引用一起改名，使用新 extractor 配置重新执行。错误类型引用也保留错误类型，不通过改名修正。

两条轨迹分别核对接受/拒绝、消耗事件和停止行为，然后比较完整投影。第二条轨迹为 **ID 改名控制**，由相同合成提案生成，不是第二个模型预测、独立正确状态或独立样本。

## 图结构

`project_graph(state, trusted_events)` 先验证严格状态结构及哈希、可信连续历史、决策截止点、来源历史哈希和唯一用户引文/位置。节点身份仍用类型、来源事件、精确引文与完整 subjects 建立键；重复 ID 或重复身份候选拒绝为 `lifecycle_graph_ambiguous`。

| 内容 | v3 保留和核验的字段 |
| --- | --- |
| 约束 | 原 predicate、subjects、来源/创建时点、lifecycle、interpretation、按顺序的更新事件、同类型 supersedes 引用 |
| 授权 | 变更类型/细节、完整条件、全部约束引用，及与约束相同的生命周期/来源信息 |
| 更新事件 | event_id、seq、完整可信事件哈希；必须在条目创建之后、当前截止点之前，来源为用户，按严格顺序且不重复 |
| 替代关系 | 新条目到旧条目的有类型边；目标须更早创建、同范围、为 superseded，并有且只有一个后继且最后更新来源对应替代事件 |
| 历史例外 | 例外到授权、到约束的边；完整 subjects、变更种类、条件及创建时点必须与其授权相符；授权有局部引用时，历史例外不能被省掉 |

所有引用必须唯一、可解析且类型正确。跨事件替代的时间递增关系阻止自引用和环；同事件内部生命周期链未纳入本版本。原生内核不支持撤销约束，因此此类状态拒绝。已撤销或已替代的条目及其例外保留；重授权不自动建立到旧撤销许可的替代边。

例外额外保存 `lifecycle_reasons` 多标签及 `lifecycle_gate` 摘要：authorization_revoked、authorization_superseded、constraint_inactive、authorization_ambiguous 或 active_scope_candidate。多个原因同时存在时全部保留。摘要按授权失活、约束失活、歧义的顺序选择；它仅描述生命周期，**不是候选覆盖结论**，不能替代对象/操作/条件判断。

投影保留原 predicate 和条件，不推断语义等价。任务背景继续走独立 M3i 账本；此授权图入口遇到非空内嵌 task_context 明确拒绝。结果拥有独立的嵌套数据副本，调用者后续修改输入不能改写已生成图。

## 校验边界与输出

单独投影只检查快照内在结构与来源/时间一致性，不能证明某次更新提案获得了合法授权；运行入口还必须完成原批次回放和改名控制重执行。改变生命周期、歧义或条件会保留为图差异；缺失更新历史、错误类型、悬空引用、替代环、例外与授权不符等直接拒绝 `lifecycle_graph_invalid`。

`diagnostic.json` 保存来源审核哈希、源码哈希和每组前缀的接受/拒绝、原/改名状态哈希、图哈希及例外生命周期摘要；`evaluator_graphs.json` 保存改名映射、扩展状态两侧投影与改名批次记录。两者均为 evaluator_only。拒绝分支不产生有效终点评估，也不尝试计划中的后续扩展。`verify` 重新验证来源、重放并逐文件比较，不仅信任保存的图哈希。

本次验收覆盖六个已有合成分支；未穷举全部多目标更新、同事件替代链或任意自然语言。旧真实诊断、样本数量及提供商费用不变；人工时间和本次离线耗时未测量时记 unknown，不生成方法成绩。
