# S3 增量交互 v3：按需历史可见性

状态：开发诊断候选；尚未获真实运行授权。适用案例为当前公开合成历史 c001/c002/c003。本规格不授权新的 provider 请求。

## 请求可见性

运行器可访问完整可信公开历史并保留完整证据哈希。增量模型请求只显示：

- 当前决策事件的完整内容；
- 截止当前事件的先前状态和已接受任务背景；
- 更早事件的 `event_id`、`seq` 和 `role` 索引；
- 同一公开证据包、代码/契约材料、工件登记和工具权限。

更早事件正文默认不进入模型请求。模型可提交互斥的 `lookup_request`，指明已知且不超过当前时点的事件 ID。运行器仅在请求通过截止点、每次事件数、总次数与成本闸门后，返回被请求原文用于续答。超额、未知或未来 ID 整体拒绝并按失败规则停止该轨迹。不得从私有审核材料、作者参考状态、其他方法输出或未来事件构造返回内容。

此为“按需历史”方法的明确输入策略，与完整上下文基线一次性展示全部历史不同；只能用于开发诊断，不据此宣称相同信息时点、预算匹配或方法优劣。原始证据包哈希相同代表来源相同，不代表初始请求的文本可见内容相同。

## 事件来源及动作

- trusted user 事件的任务背景/状态变更必须引用当前事件中唯一精确原文。若决策需要此前用户原文，可自主请求回查，不能把旧引文写成当前来源。
- tool/assistant/system 事件不能建立任务背景、约束或授权。仅允许空 `task_context` 与单项 `no_change`，其 `source_quote` 必须来自当前事件并只标记无操作出处；来源引文不增加语义权威。
- 缺少当前用户事件时，`no_change` 仍保留事件进度以便逐步回放，但不得把工具内容复制成用户意图。
- 其余操作继续使用 `interaction_quote_v2` 的互斥操作形状、唯一引文、可信角色、时点、范围匹配、原子批次和失败停止。非法输出不清理、不猜测、不自动重试。

## 验收与结果分类

离线请求构造证明旧文本被遮蔽、事件索引与证据哈希保持，且回查原文只在续答请求中出现。固定脚本回查只验接口及回放，分类 `offline_transport_only`。只有新授权真实模型自主请求、对应原文确已返回、续答通过并产生有效终点时，才记录真实回查路径已触发。未触发记 `not_exercised`；失败或无终点保留失败，不补跑。

建议本轮候选：三条增量轨迹各最多 5 次提取、2 次回查续答、1 次终点；单并发、90 秒、无重试；普通错误停止当前轨并继续下一案例，预算/完整性错误停止全轮。具体预算及新鲜价格必须由冻结计划确定，且每次真实运行另行授权。
