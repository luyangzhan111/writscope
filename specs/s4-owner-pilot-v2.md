## 复用与版本

维护入口 `scripts/s4_owner_pilot_v2.py` 薄接线到已有 owner-pilot 的执行器、单SQLite账本、HTTP进程、总期限、一次性终端启动及独立R4回放。方法算法、状态/来源/范围/生命周期/条件/精确值内核均未复制或放宽。

v1的旧全目录源码发现会受新增文件影响。新入口提供固定旧候选SHA锚定的只读v1回放：逐个核对旧215份源码/配置，忽略与该版本无关的新增文件；旧运行计划必须完整匹配固定SHA。此兼容只用于读取旧记录，不能启动旧计划。v2绑定旧清单加明确的8份新契约/提示/接线文件，避免以后新增文件破坏保存证据的可回放性。已绑定文件变化仍拒绝。

接线使用单并发进程内上下文注入；退出或异常时恢复原函数。不能同时运行两个版本入口。由新CLI进行prepare/offline/verify/run；不直接把v2候选交给旧CLI。

## 输出形状

共同提示明确 API response_format.type=json_object 是传输选项；方法返回对象必须用kind，不能回显type。所有终点只允许kind=final加payload；允许回查时为kind=lookup和event_ids。清单payload必须有非空对象checklist的六项内容，保留重建、逐影响与完整历史强基线，不删减清单。

增量kind=batch的items复用既有S3操作分型模型，再加S4 value_scope：

| 操作 | constraint | authorization | targets/supersedes | value_scope |
| --- | --- | --- | --- | --- |
| add_constraint | 必有 | null | 两者为空 | null |
| grant | null | 必有 | 两者为空 | 仅匹配的语义变更许可可非空 |
| supersede约束 | 必有 | null | 非空且顺序一致 | null |
| supersede许可 | null | 必有 | 非空且顺序一致 | 同grant |
| revoke、mark_ambiguous | null | null | target_ids非空且唯一 | null |
| no_change | null | null | 空 | null；单项独占批次 |

JSON schema暴露各分支字段互斥、空/非空列表及no_change独占。动态列表等值、重复目标及value_scope与授权/引文一致性继续由运行时校验，再交给原内核。接收时不删字段、不改kind、不拆坏项、不修复JSON；始终解析实际原文。失败在响应校验阶段记录结构错误路径/类型/说明，不把原始输入值或推测修复写成成功。失败仍计费且保留三任务分母。

提示明确客户端本地映射属于任务背景，不能产生服务端grant；独立有据的约束仍可提取，其余背景保留于既有可见历史。本版本不增加基于关键词的语义判定器，不声称schema能证明自然语言许可成立。宽范围约束、局部例外和原来源/范围检查不变。

旧真实清单与增量原响应在v2仍应被拒绝，只能证明新schema更早识别错误。合成正支需由公开材料独立构造，并按模拟标注，不能把修过的原响应称作模型改进。真实模型是否遵守新提示尚未验证，不输出模拟准确率。
