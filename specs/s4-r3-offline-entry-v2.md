# S4 R3 离线维护入口 v2

日期：2026-11-02。维护入口为 `scripts/s4_r3.py`。它复用既有检查点执行器、固定 MockTransport 与 SQLite 账本，不复制语义执行算法；原有版本文件和原始工件继续用于历史复验。该入口不能读取真实凭据或发送真实请求。

## 计划与授权来源边界

`prepare` 绑定调度、完整公开包、提示词及 schema 的实现源码、依赖、模拟脚本、实际模拟请求所用模型字段（deepseek-flash / temperature=0 / max_tokens=4096）、固定 mock.invalid 地址、公开材料范围、价格有效期、虚拟费率、最大次数、单并发无重试。该模型字段只描述模拟序列化内容，不代表选择或调用了真实模型。虚拟字节预留不是实际 token 或货币上界。

`start` 接受来源事件 ID，以及由控制层单独提供的 `ApprovalSource.resolve(event_id)`；不从请求 JSON 构造来源。适配器的责任是从已认证的系统获取原始人类事件及其精确批准范围，保留可复查的事件 ID、角色、主体、正文、时间、撤回状态。核验层将这些信息与固定负责人 ID、计划哈希、收件方、逐项材料范围和上限比较。旧 S3 授权、工具消息、自报 approved、撤回/过期/未来批准、错误主体或范围均拒绝。

**本仓库没有安装生产环境的已认证来源适配器。** 默认缺少来源即拒绝；离线测试通过单独配置的合成适配器验证接口，只接受 `synthetic=True` 且目的为 `offline_test_only` 的证据。适配器是信任边界，不是靠 dataclass、哈希或 source 字符串生成真实性；同进程恶意代码不在保护范围。任何真实证据在此离线入口也不能启动发送，`start_real` 无条件拒绝。实际用户批准属于 R6/R7 的真实接入，不把测试记录或负责人四项语义确认当成运行批准。

校验和公开输入白名单检查发生在创建 claim 前；再以独占创建、flush/fsync 写入合成 claim，记录原始测试证据、精确计划哈希和输出位置。之后检查点数据库绑定同一计划。拒绝不消耗 claim；一旦 claim 存在，无论中断前后都不自动重用。未创建成功的目录不会伪装成运行完成；人工恢复需另立计划。此处仅保证本地文件系统的一次性启动，不声称分布式锁或操作系统隔离。

## 停止与收尾

状态路径：预留 → 发送开始 → 响应保存 → 校验完成/失败。预留未标记发送不算尝试，发送后超时或进程中断不退还预留；保留所有计划任务。每次发送前重验计划、输入和来源文件的绑定。普通错误停单轨，额度、来源、隔离、账本或持久化错误停全轮。

虚拟预算/次数耗尽时保持 `run.stopped=synthetic_budget_exhausted`。只允许最后一个已启动且尚未结束任务追加一次 `job_finished`，其状态必须为 failed/not_run、原因必须为 round_budget_exhausted，且没有未决传输。该事务重新检查计划/策略绑定和重复终点，永不清除 stopped。新预留、新任务和重复收尾一律拒绝。若合法收尾本身真正写入失败，摘要保留持久化错误，账本仍保留预算原因，不能掩盖两个事实。

## 核验与后续交接

`inspect` 使用 SQLite 只读模式，核对完整分母、计划和请求绑定、已有响应、轨迹与检查点，列出未决尝试和局部操作，并接入共同成本汇总。成功的回查、状态更新、评估和验证耗时可累加；失败未完成及共享证据制作耗时仍 unknown，不合成零。该检查不承担 R4 独立语义重放或引用支持度评测。

R3 离线验收包含新旧预算故障对照、模拟成功/回查、授权拒绝、竞争启动、普通错误、进程中断、来源隔离及真实入口关闭。30 例 R=3 全批仍属于 R5；正式模型/真实价格冻结属于 R6；实际人类批准后的发送属于 R7。无需为了本步请求密钥、预算或外发授权。
