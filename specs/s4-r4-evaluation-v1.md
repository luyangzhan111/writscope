# S4 R4 保存轨迹验证与评测契约 v1

2026-11-02。对接 `s4_r3_offline_v2` 和 R2 单 SQLite 账本；本契约另立版本，不修改旧运行器、响应、参考、评分或哈希绑定。维护入口为 `python -m scripts.s4_r4_evaluator verify|evaluate`，库接口为 `s4_r4_replay.verify` 和 `s4_r4_evaluator.evaluate`。两者均只读执行记录，没有发送、密钥读取、授权批准或自动续跑功能。

## 验证顺序与信任边界

1. 核对 R3 计划、源码、提示词、schema、完整公开包白名单和 `(case_id, method, track, repeat_index)` 全清单；三方法与连续 repeat 由重建计划确定。重复、缺项、重排、未计划任务均拒绝。
2. 只读打开已关闭的 SQLite 快照，检查预留金额、次数、请求/响应字节哈希、检查点链和停止状态。运行前后比较文件哈希，活动 journal/WAL 文件拒绝。所有未完成预留仍占预算。
3. 从空状态开始，只解析账本中**已收到**的响应。按阶段与可见历史重建请求字节，与实际持久化字节逐一比较；来源角色、截止点、原文回查、续答、原子状态转换、精确范围和最终输出使用既有公共契约内核校验。检查点是待核对证据，不是重建状态的输入。无工具执行权限升级。
4. 独立核对阶段顺序、时间因果关系、finish reason、响应大小、验证/错误状态、持久化状态与任务文件/全轮摘要。普通错误停单轨；实际金额/次数不足须能从下一次请求与已有预留推导；停止后新增任务或续发拒绝。失败和未运行保留全部计划分母。
5. 只有完整且已结算的轨迹才打开评测器私有清单。检查 reference/disposition/audit/method-policy/负责人有限决定/原 R1 包的固定哈希和交叉关系；逐例公开包须匹配 P3 审核记录中的整个 bundle 哈希与决策时点。编号相同但版本不同也拒绝套用标签。

验证器不调用 `execute`、不解析 `Script`、不与原 mock 预期响应比较。`--scripts` 仅用于原计划的文件哈希绑定。合法的不同响应可以复验；这证明与预设答案的解耦，**不证明响应来自真实 provider**。解析器、范围/状态内核与运行器共用，独立性指记录驱动的验证流程，不是独立实现或独立人工审核。

当前唯一支持的记录来源是明确的 `offline_mock`。任何真实或未知来源标记均拒绝；`mode` 除 `synthetic_diagnostic` 外一律拒绝。哈希一致不能证明真实发送、真实批准、引用语义正确或没有人为改写整套材料。未来真实记录必须另立已认证来源与冻结计划适配器，不能只改标记。

## 中断与失效输出

`verified_settled_synthetic` 表示完整记录通过结构/来源/状态/账本复验，可做合成算法检查。`verified_prefix_only` 表示只能验证保存前缀，仍列出全部计划任务、已发或不确定次数、未发送预留与 unknown 成本；评测入口返回 `incomplete_evidence_no_reference_read`，不读私有参考、不计算指标。

未收到响应、已收到但未完成验证、缺检查点、缺持久化任务文件或全轮完整性故障都不能补造成功。中断后的任务状态是保守的评测映射，另存 `incomplete`，不是恢复后的执行状态。已发或发送不明记 failed；仅预留但未发送记 not_run。源文件/公开包/哈希损坏直接拒绝，原始证据保留。

合法增量终点与重建状态三轴不一致时，主结果 `failed`、`prediction=null`，仍计主分母。只有原终点先通过公共输出校验时，才另存 `diagnostic`：原始三轴、差异轴和响应哈希。诊断不能替换主结果；非法来源、未来引用、错误结构不能以诊断名义拿到有效终点。

## 评测输出

`s4_r4_evaluation_v1` 绑定计划、原始工件、评测器私有版本、重建结果和成本。逐轨保存三轴或无输出、失败/中断、引用检查、诊断和成本；按方法/轨道输出：

- 影响维度保留所有计划行；授权主分母由**参考 breaking 且非争议**确定，不能按预测或成功行筛选。
- 授权全部适用范围、决策、三轴同时正确、误放行、传统误拦截、包含缺失的合法未放行、ask 过用和两例歧义单列。
- s4_018/s4_020 不进授权/决策主分母，仍进影响分母；按已记录的负责人有限决定执行，不宣称 30 例逐例签收。
- 配对必须完整且同 repeat，报告原始分子、分母、无有效输出数。部分切片只有一侧时显式列为 `incomplete_pairs_excluded`。保留 12 个开发配对的限制，不称严格单变量。
- `synthetic_diagnostic_counts` 仅供算法/接线核验；`model_metrics=null`、`accuracy=null`、`scoring=not_scored_scripted_mock`。不据此发布方法准确率、排名或优劣结论。
- 引用可解析、原文位置、角色、时点有效与语义支持分开。没有实际语义审核时 `semantic_support=not_evaluated`，不是支持成立。

主比较为等配置；预算匹配后置另立计划。项目参考保持 provisional，独立审核为 `not_performed_skipped_by_user`，正式数据冻结和真实执行许可均未发生。

## 成本与未覆盖能力

逐轨、逐方法/轨道和全轮汇入共同成本契约；提取、回查续答、终点、状态更新、回查/评估/验证及失败耗时均计入。未发送预留不计 provider 尝试；超时/中断不释放预留。token、缓存、推理用量、实付和估算未知保持 null；已知小计、未知数、完整总额分开。虚拟预留不是货币、实际 token 或账单硬上界。共享证据制作耗时当前 unknown。

当前 R3 未保存独立的验证完成时间戳；R4 只能检查已有预留/发送/接收/检查点时刻及单调关系。持久化失败只复验已落盘前缀，不猜测丢失的工作量；不提供自动续跑。全批 30 例 R=3、恢复交付检查属于 R5；真实 provider 来源证明、正式模型/价格/参数冻结与精确新计划的费用及外发批准属于后续前置条件。所有真实发送继续关闭。
