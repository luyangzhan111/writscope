# S4 R5 同版本离线验收与交付契约 v1

2026-11-02。本版本冻结的是离线工程验收候选，不是正式数据、模型、价格或人类授权。真实发送保持关闭，独立审核为 `not_performed_skipped_by_user`。

`scripts/s4_r5_acceptance.py` 只生成公开证据副本、固定合成脚本、测试控制源及故障注入；实际方法执行完全委托 R3 v2，复验与评测完全委托 R4 v1。原文件及旧记录不修改。脚本由公开包生成，既不采用作者标签也不把参考、配对或答案放进请求。

全批维护检查使用 `s4_r5_integrity_guard.ByteEquivalenceGuard`：初始两次调用原 R3 完整语义准入，中间捕获公开包、脚本及全部绑定源码的原始字节哈希与文件清单；每次发送前仍重新读取并哈希每个文件，核对清单、链接、计划及输入根。只省略对字节未变文件的重复 JSON/模型解析；不依赖 mtime 或文件大小缓存，任一字节变化即停止。R4 仍用原完整校验独立复验。此封装仅在离线验收子进程生效，不改 R3 文件或开放真实发送。

每个场景计划明列 30 例 × 三方法 × 重复 3 次，共 270 条任务。共同工程源码哈希固定；场景之间只改变显式列出的合成响应、虚拟额度或故障注入点，不能据此比较方法性能。设计尝试上界从公开历史长度与当前回查规则重算；实际次数来自记录，不能固定为旧值 657。常规错误只停止单轨；预算、来源、隔离、账本故障及中断停全轮，未知量不归零。

场景包括正常全批；同一全批内的 provider/schema/状态普通错误；金额和次数不足；来源检查注入、检查点哈希、公开输入白名单及账本故障；预留、发送开始、响应收到、验证保存、更新开始/结束等进程强制退出窗口；任务文件/汇总写入失败。另从正常记录派生重复任务、缺失任务、伪造真实来源控制。全部保留原始负例，不修补故障现场后再声称原记录通过。

硬退出使用独立测试进程，注入位置先写 `fault-fired.json` 再退出。测试进程禁止 socket connect；合成控制源不等于实际批准。每个场景只允许新目录和一次启动；中断后不自动续跑。需要另做验证时只能只读检查保存记录，或另立完整新工程候选。

R4 完整记录返回已验证合成结果；中断或落盘不完整返回仅前缀；哈希、隔离、账本损坏拒绝验证。后两类均不得读取参考。即使评测器拒绝，完整任务清单仍在候选与原始计划中保留，不能删除失败项或输出伪造分数。

`scripts/s4_r5_delivery.py` 从明确的源码目录、锁文件、精选旧证据及本轮场景目录构建 ZIP 与逐文件哈希清单。排除 Git 内部、虚拟环境、缓存、凭据目录和所有 `.env*`；包内标注评测器材料，交付包本身不是方法输入包。恢复前验证路径、重复项、大小和每项字节哈希，只能写入新目录，不覆盖旧文件；拒绝目录穿越、链接与损坏档案。

恢复核验在新进程、全新源码目录下进行，逐场景重算报告并与原报告比较；运行无密钥公开演示及旧 S3 v8 成功/v7 失败代表性只读回放，最后再次核对归档原字节。使用已有项目 Python 环境里的依赖，并记录实际版本；不复制 `.venv`，不联网安装，不能声称另一个操作系统或全新依赖环境已经验证。源码导入必须来自恢复目录，不能回落原工作区。

交付证据包括工程候选、场景清单、进程状态、故障注入点、原始 SQLite/逐轨文件、R4 报告、矩阵、ZIP 与清单、恢复核验和测试记录。Git 忽略的原始目录通过明确归档恢复，不只留下本机绝对路径。历史 claim 原路径保留，兼容视图只用于只读复验，不能转换成新的运行许可。

R5 通过只表示可以进入 R6 的候选冻结准备。项目参考仍 provisional、逐例审核未签收，预算匹配后置，真实来源/批准适配器和精确新计划的费用与外发批准仍缺。无自动真实执行、GitHub 更新、模型评分或方法优势结论。
