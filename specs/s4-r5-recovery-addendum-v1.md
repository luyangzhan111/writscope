# R5 恢复兼容补充 v1

2026-11-02。原 R5 工程候选、源码哈希、ZIP 与 16 个场景不改。本补充只替代 Windows 上的恢复检查编排；方法执行仍为 R3 v2，响应回放仍为 R4 v1。

原恢复命令在 16 份报告重算完成后，因断网保护拦截 Windows `asyncio` 创建内部唤醒 socket 而失败。`scripts/s4_r5_recovery.py` 在运行任务前建立本地事件循环，然后在禁止 socket 连接的保护下执行公开离线演示和历史只读回放，仍验证真实入口在触碰凭据/发送回调之前拒绝。

默认从新目录完整重算 16 份报告。仅在既有恢复尝试已保存全部完整重算结果时，显式 `--reuse-recomputed` 可以逐份核对它们与原报告相等，完成剩余检查；收据必须标为复用已重算报告，不能冒称本补充又做了一次完整回放。首次失败、未成功完成的环境尝试和已有报告均保留。

补充文件通过包旁 `recovery-addendum.json` 单独绑定，安装到恢复树时只新增该脚本，不覆盖原文件。它不加入原运行候选的 60 份源码绑定，也不宣称运行前已冻结。最后仍须执行原 `verify-restored` 验证全部 3,085 份归档原字节，补充源码由自己的清单和收据核对。

受限环境若阻塞本机事件循环通信，应停止并记录环境中断；不能把中断当通过，也不能取消实际演示/回放期间的外部连接保护。此次使用获准的本机执行环境，未读取实际密钥、调用模型、外发材料或产生费用。
